## 建议学习顺序

1. **请求先活下来：** API Engineering → Latency。画出一次 FastAPI + Gemini / RAG 请求，手算串并行关键路径、超时和首 token。
2. **规模与账单：** Cost → Scaling。手算 10 万用户/天的模型费，补齐请求次数、峰值 QPS、并发与下游配额。
3. **线上有据可查：** Observability → Reliability。用 trace 定位慢、贵、错和未知副作用，再设计安全降级与故障演练。

## Suggested order

1. **Keep requests bounded:** API Engineering → Latency. Trace a FastAPI + Gemini/RAG request, timeouts, and the critical path.
2. **Size usage and spend:** Cost → Scaling. Calculate monthly spend for 100k daily users, then peak QPS, concurrency, and provider limits.
3. **Operate with evidence:** Observability → Reliability. Trace slow, expensive, wrong, and uncertain outcomes before designing fallbacks and drills.

All six pages are bilingual Levels 0–4, using order `20240915` and current policy `P-17 v3` as a teaching case. Illustrative numbers are not personal project measurements. Practice with `/drill production/<page slug>`; generated notes do not count as mastery.
