## 三级回答

### Level 1 — 定义

LLM 是一个高延迟、会限流、会部分失败的 HTTP / RPC 依赖。

### Level 2 — 机制

流式输出改善的是首 token 的体感。超时要分成连接超时、首 token 超时和总时长超时。限流和退避既保护你自己，也保护供应商。

### Level 3 — 工程

对不幂等的工具不要盲目重试。连接池和异步决定你能扛多少 QPS。接到 Voice 项目的流式输出。

## Three-level answers

### Level 1 — Definition

An LLM is an HTTP / RPC dependency that's slow, rate-limited, and partially fails.

### Level 2 — Mechanism

Streaming improves how fast the first token feels. Timeouts should be split into connect, time-to-first-token, and total duration. Rate limits and backoff protect both you and the provider.

### Level 3 — Engineering

Don't blindly retry non-idempotent tools. Connection pooling and async decide how much QPS you can handle. This connects to streaming in the Voice project.
