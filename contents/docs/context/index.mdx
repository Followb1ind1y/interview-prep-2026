## 学完后应该能做到

1. 画出客服两轮调用，指出模型本轮实际收到什么
2. 给一次请求做 token 预算，并用同题实验测证据位置的影响
3. 从 20 段资料选出足够的证据，解释错误发生在检索、组装还是生成
4. 从示意 100K 历史压到 20K，仍保留来源、版本、未完成动作与不确定性
5. 分清三层缓存；在政策变化、订单变化、跨租户场景下设计失效与拒绝测试

Context engineering asks: **what should the model see for this step, what remains external, and what must never cross an authorization boundary?** Work through Model Context → Window → Construction → Compression → Caching → Isolation. All six pages follow the same cat-food support case.

## What you should be able to do

1. Draw two support calls and show exactly what the model received each time.
2. Budget one request and test evidence position on identical questions.
3. Select enough evidence from 20 passages and locate failures in retrieval, assembly, or generation.
4. Reduce an illustrative 100K history to 20K while preserving provenance, versions, pending actions, and uncertainty.
5. Separate three cache layers; test invalidation and denial after policy, order, and tenant changes.
