## 三级回答

### Level 1 — 定义

围绕当前这一步的目标，组装「最小但足够」的上下文。

### Level 2 — 机制

用检索、规则、权限和工具相关性来做筛选。顺序同样有意义：指令、证据、问题。

### Level 3 — 工程

工具定义太多，会干扰模型选工具。历史太长，会淹没当前的问题。这和 Agent 的可靠性、成本是同一个杠杆。

## 面试问题

1. 什么应该进入 context？（What should go into the context?）
2. 工具很多时，怎么避免把它们全部塞进 prompt？（With lots of tools, how do you avoid putting all of them in the prompt?）
3. 检索回来 20 段，怎么选出 5 段、怎么排序？（You retrieved 20 passages — how do you pick 5, and how do you order them?）
4. 怎么区分是 context 拼装失败，还是检索失败？（How do you tell a context-construction failure from a retrieval failure?）

## Three-level answers

### Level 1 — Definition

Assembling the smallest context that's still sufficient for the goal of the current step.

### Level 2 — Mechanism

Select with retrieval, rules, permissions, and tool relevance. Order matters too: instructions, then evidence, then the question.

### Level 3 — Engineering

Too many tool definitions confuse tool selection. Too much history buries the current question. It's the same lever that drives agent reliability and cost.
