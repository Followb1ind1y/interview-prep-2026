Evaluation 要回答的不是“有一个分数吗”，而是：**系统对哪些真实任务更可靠、哪些风险仍未验证、故障发生在哪一层？** 六页沿用猫粮客服退款案例，按 Fundamentals → Offline → LLM → RAG → Agent → Production 的依赖顺序学习。

想查具体指标：先到 [Fundamentals Level 2](/docs/evaluation/fundamentals) 手算混淆矩阵、Accuracy、Precision、Recall、F1 和分母；[LLM Evaluation](/docs/evaluation/llm-eval) 用 Judge 分项评价多轮对话质量、算偏好胜率并审计漏放；[RAG Evaluation Level 1–2](/docs/evaluation/rag-eval) 讲 Recall@K、Precision@K、MRR、nDCG 与有据性；[Agent Evaluation](/docs/evaluation/agent-eval) 看任务状态、工具调用与副作用；[Production Evaluation](/docs/evaluation/production-eval) 看已验证成功率、覆盖率和待验证结果。名字相似的指标要先说清**评测单元、正类、真值、分母和错误代价**。

## 学完后应该能做到

1. 为一个客服决策写出输入、环境真相、期望行为和可评分状态，并解释分母
2. 建覆盖常见流量与高风险边界的离线集，比较两个版本的逐题修复和回归
3. 给开放式回答选对 grader，校准 Judge 与人工；手算 RAG 检索指标
4. 验收 agent 的真实业务状态和轨迹，测试超时、越权与重复写入
5. 用线上 trace、成熟结果和受控放量，将故障转成有标签的回归 case

Evaluation asks more than “do we have a score?” It asks **which real tasks became more reliable, which risks remain unverified, and which layer failed**. All six pages follow one cat-food support refund case in dependency order: Fundamentals → Offline → LLM → RAG → Agent → Production.

For concrete metrics, start with [Fundamentals Level 2](/docs/evaluation/fundamentals) for confusion matrices, Accuracy, Precision, Recall, F1, and denominators. [LLM Evaluation](/docs/evaluation/llm-eval) grades multi-turn dialogue quality by dimension, calculates pairwise win rate, and audits judge misses. [RAG Evaluation Levels 1–2](/docs/evaluation/rag-eval) covers Recall@K, Precision@K, MRR, nDCG, and groundedness. [Agent Evaluation](/docs/evaluation/agent-eval) measures task state, tool use, and side effects. [Production Evaluation](/docs/evaluation/production-eval) separates verified pass rate, coverage, and pending outcomes. For similarly named metrics, state the **unit, positive class, ground truth, denominator, and cost of mistakes**.

## What you should be able to do

1. Define input, environment truth, expected behavior, and scoreability for a support decision; explain the denominator.
2. Build an offline set with common traffic and risky edges; compare fixes and regressions case by case.
3. Choose graders for open text, calibrate judges with people, and calculate retrieval metrics.
4. Verify real agent state and trajectory under timeout, denied access, and duplicate writes.
5. Use production traces, mature outcomes, and controlled rollout to turn failures into labeled regressions.
