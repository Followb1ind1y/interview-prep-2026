Many phrasings can correctly explain one refund decision. Exact string matching rejects good answers, but asking a judge model whether a response “looks good” may let a false promise through. **Choose a grader for the property being tested.**

Following [Fundamentals](/docs/evaluation/fundamentals) and [Offline](/docs/evaluation/offline), start with deterministic checks, understand semantic measures, design an anchored LLM judge and pairwise comparison, then calibrate against human labels. The running case is the reply for order 20240915.

- Know what exact match, BLEU/ROUGE, and embedding similarity measure; similarity is not factual correctness.
- Give judges one observable dimension, input, evidence, rubric, output schema, and an uncertainty option.
- Blind pairwise comparison, swap answer order, allow ties; validate any claim of stability on the task.
- Check false passes against human labels, pin judge versions, and monitor drift and grading cost.

## Level 0 · 先选对尺子

### 为什么不能只用 exact match 或 embedding 相似？

若目标是 `decision=not_eligible_for_unshipped_refund`，结构化决策字段可做 **exact match**。若目标是“不要调用退款写工具”，可查真实工具 trace / 数据库状态。二者比让 LLM judge 猜测更直接。

**BLEU/ROUGE** 衡量候选与参考文本的词或片段重叠，适合了解表面相似度，不能证明业务事实正确。**Embedding similarity** 测语义接近，也可能把“可以退款”与“不能退款”判得很像，因为两句主题相同、只差否定。对于客服自然语言的清晰度、完整解释等开放属性，可引入人或 LLM judge。

把同一回答拆开检查：

```text
回复: “订单运输中，按 P-17 不能走未发货退款；请联系退货流程。”
决策字段          → 规则/精确匹配
是否真的运输中    → 订单系统与查询时间
政策引用有效      → 当前版本条款校验
解释是否清楚      → 人工或 rubric judge
是否执行了退款    → 写操作记录
```

## Level 0 · Pick the right ruler

### Why not use only exact match or embedding similarity?

For a structured target such as `decision=not_eligible_for_unshipped_refund`, **exact match** is useful. To check “do not call the refund write tool,” inspect the actual tool trace or database state. Both are more direct than asking a judge model to infer what happened.

**BLEU/ROUGE** measure text or n-gram overlap with a reference; they say little about business correctness. **Embedding similarity** measures semantic closeness and may rate “refundable” and “not refundable” similarly because the topic is almost identical except for negation. Human review or an LLM judge fits more open properties such as clarity and explanation completeness.

Split one answer into checks:

```text
Reply: “The order is in transit; under P-17 it cannot use the
        unshipped refund flow. Please follow the return process.”
Decision field          → rule / exact match
Actually in transit?    → order system and query time
Policy citation valid?  → current versioned clause
Explanation clear?      → human or rubric judge
Refund executed?        → write-operation record
```

## Level 1 · 写出可审核的 Judge

### Rubric 怎样把“回答好不好”变成判断标准？

让评审只判一个轴，例如“是否作出有证据支持的退款判断”，并给它**问题、订单与政策证据、候选回答、判定规则**。示意评分合同：

```text
输入: 用户问题 + 已核实订单状态 + 当前政策条款 + 候选答复
输出: {verdict: pass|fail|uncertain, cited_claims: [...], reason: ...}
pass: 不承诺与状态/政策冲突的退款；说明依据和下一步
fail: 承诺不允许的退款、编造订单状态或引用旧版政策
uncertain: 关键证据缺失或相互冲突
```

这里的 `pass|fail|uncertain` 在代码块里作为示意，实际 JSON Schema 应用枚举。让 judge **标出具体主张与证据**，便于人工复核；但理由文本不保证一定真实，仍要与原始 trace 对照。固定被测输入、judge 模型和 rubric 版本，否则分数变化可能来自尺子变了，而不是系统变了。

不要把风险不同的维度压成一个 1–5 分。可以分别判“决策”“证据”“语气”，关键错误单独触发 hard fail。Judge 自身看到的资料范围也要足够：没给订单状态，它不能可靠判断退款资格。

## Level 1 · Write an auditable judge

### How does a rubric turn “good answer?” into criteria?

Ask a judge to assess one axis, such as “is the refund decision supported?” Supply the **question, verified order and policy evidence, candidate reply, and criteria**:

```text
Input: question + verified order state + current policy + candidate reply
Output: {verdict: pass|fail|uncertain, cited_claims: [...], reason: ...}
pass: no promise conflicting with state/policy; explain basis and next step
fail: promise forbidden refund, invent status, or cite obsolete policy
uncertain: decisive evidence missing or conflicting
```

`pass|fail|uncertain` is illustrative notation; an implementation should use a real enum schema. Ask for specific claims and evidence so humans can audit decisions, but a judge's explanation can also be wrong. Compare it with source traces. Pin test inputs, judge model, and rubric version; otherwise score changes may reflect a changed ruler.

Do not collapse axes with different risks into one 1–5 score. Grade decision, evidence, and tone separately, and treat critical errors as hard failures. The judge also needs sufficient evidence: without order state it cannot reliably decide eligibility.

## Level 2 · 成对比较与偏差

### A 比 B 好，怎样问得更公平？

若 A 与 B 都答对退款资格，但措辞和解释不同，成对比较让 judge 在**相同问题、证据与标准**下选更好的答案。它通常比“各打一个抽象 1–5 分”更容易定义差异，但不是天然无偏。给匿名的 A/B，交换展示顺序，再观察是否翻转；允许 **平局** 和“证据不足”。

例：A 用 30 字给对决策但缺下一步；B 用 120 字给对决策并清楚列下一步。若 rubric 看重完整性，B 可能胜出；若 B 额外编造“免费退货”，应判失败，不因更长、更自信而获胜。LLM judge 可能有**位置、冗长、风格或同系列模型偏好**；研究已观察到这些偏差，具体大小依模型与任务变化。[MT-Bench/Chatbot Arena 研究](https://arxiv.org/abs/2306.05685)

对于“是否发生越权写入”这类事实，别用成对偏好来决定。成对比较适合难以给绝对分的表达质量或整体偏好，但事实与安全条件应由独立确定性检查优先覆盖。

## Level 2 · Pairwise comparison and bias

### How do you ask whether A is better than B fairly?

If both A and B make the correct refund decision but differ in explanation, pairwise comparison asks a judge to choose under the **same question, evidence, and criteria**. It can be easier to discriminate than assigning two abstract 1–5 scores, but is not bias-free. Blind the names, swap display order, and allow **ties** or “insufficient evidence.”

Example: A gets the decision right in 30 words but omits the next step; B explains it in 120 words. B may win for completeness. If B also invents “free returns,” it should fail despite length and confidence. LLM judges can exhibit **position, verbosity, style, and model-family biases**; their sizes vary by task and model. [MT-Bench/Chatbot Arena study](https://arxiv.org/abs/2306.05685)

Do not use preference voting to establish whether an unauthorized write occurred. Pairwise grading suits expression quality or overall preference, while factual and safety constraints deserve direct checks.

## Level 3 · 用人工标签校准 Judge

### 如何量化“Judge 大体同意人工”？

在**10 个教学样本**上，专家确认 6 个通过、4 个失败。Judge 的混淆表如下（“正”=应通过）：

| | 人工通过 | 人工失败 |
| --- | ---: | ---: |
| Judge 通过 | 5 | 2 |
| Judge 失败 | 1 | 2 |

一致数为 `(5+2)/10 = 70%`；更关键的是 **false pass = 2/4 = 50% 的人工失败被放过**。这么小的样本只用于手算，不能稳定估计总体表现。若两条假通过都是越权退款，judge 不适合作为唯一发布门槛。

校准流程：① 由业务专家标注分层样本并处理分歧；② 将 judge 判定与人工逐 case 对照，特别查看 false pass；③ 改进 rubric、证据输入、阈值或改为确定性检查；④ 在**未用于调 judge 的样本**上重测；⑤ 版本更新后持续抽样审计。也要检查不同语言、订单状态和较长回答是否有系统偏差。

<Note type="danger" title="不要让 Judge 给自己背书">

用同一个 judge 自动造标签、调 rubric、再报告与这些标签“一致”，会产生循环验证。高后果判断需要独立人或权威系统作对照。

</Note>

## Level 3 · Calibrate against people

### How do you quantify “the judge mostly agrees with experts”?

On **10 teaching cases**, experts mark 6 pass and 4 fail. The judge confusion table is:

| | Human pass | Human fail |
| --- | ---: | ---: |
| Judge pass | 5 | 2 |
| Judge fail | 1 | 2 |

Agreement is `(5+2)/10 = 70%`. More concerning, **false-pass rate among human failures is 2/4 = 50%**. Ten cases illustrate the arithmetic, not a stable population estimate. If the two false passes are unauthorized refunds, the judge cannot be the only release gate.

Calibrate by ① expert-labeling sliced cases and resolving disputes; ② reviewing case-level disagreements, especially false passes; ③ changing rubric, evidence, threshold, or using deterministic checks; ④ retesting on cases **not used to tune the judge**; and ⑤ sampling audits after version changes. Look for systematic errors across languages, order states, and answer lengths.

<Note type="danger" title="Do not let a judge validate itself">

Using one judge to create labels, tune its rubric, and report “agreement” with those labels is circular. High-consequence decisions need independent people or authoritative systems.

</Note>
