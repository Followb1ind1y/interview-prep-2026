Many phrasings can correctly explain one refund decision. Exact string matching rejects good answers, but asking a judge model whether a response “looks good” may let a false promise through. **Choose a grader for the property being tested.**

Following [Fundamentals](/docs/evaluation/fundamentals) and [Offline](/docs/evaluation/offline), start with deterministic checks, understand semantic measures, use an anchored LLM judge to score multi-turn dialogue by dimension, compare pairs, then calibrate against human labels. The running case is the reply for order 20240915.

## Must know

- Know what exact match, BLEU/ROUGE, and embedding similarity measure; similarity is not factual correctness.
- Give judges one observable dimension, input, evidence, rubric, output schema, and an uncertainty option.
- Separate relevance, completeness, context consistency, grounding, instruction following, uncertainty, and communication; report per-dimension pass rates and hard failures.
- Blind pairwise comparison, swap answer order, allow ties; validate any claim of stability on the task.
- Check false passes against human labels, pin judge versions, and monitor drift and grading cost.

## Level 0 · 先选对尺子

### 为什么不能只用 exact match 或 embedding 相似？

若目标是 `decision=not_eligible_for_unshipped_refund`，结构化决策字段可做 **exact match**。若目标是“不要调用退款写工具”，可查真实工具 trace / 数据库状态。二者比让 LLM judge 猜测更直接。

**BLEU/ROUGE** 衡量候选与参考文本的词或片段重叠，适合了解表面相似度，不能证明业务事实正确。**Embedding similarity** 测语义接近，也可能把“可以退款”与“不能退款”判得很像，因为两句主题相同、只差否定。对于客服自然语言的清晰度、完整解释等开放属性，可引入人或 LLM judge。

把同一回答拆开检查：

```text
回复: “订单运输中，按 P-17 不能走未发货退款；请联系退货流程。”
决策字段          → 规则/精确匹配
是否真的运输中    → 订单系统与查询时间
政策引用有效      → 当前版本条款校验
解释是否清楚      → 人工或 rubric judge
是否执行了退款    → 写操作记录
```

## Level 0 · Pick the right ruler

### Why not use only exact match or embedding similarity?

For a structured target such as `decision=not_eligible_for_unshipped_refund`, **exact match** is useful. To check “do not call the refund write tool,” inspect the actual tool trace or database state. Both are more direct than asking a judge model to infer what happened.

**BLEU/ROUGE** measure text or n-gram overlap with a reference; they say little about business correctness. **Embedding similarity** measures semantic closeness and may rate “refundable” and “not refundable” similarly because the topic is almost identical except for negation. Human review or an LLM judge fits more open properties such as clarity and explanation completeness.

Split one answer into checks:

```text
Reply: “The order is in transit; under P-17 it cannot use the
        unshipped refund flow. Please follow the return process.”
Decision field          → rule / exact match
Actually in transit?    → order system and query time
Policy citation valid?  → current versioned clause
Explanation clear?      → human or rubric judge
Refund executed?        → write-operation record
```

## Level 1 · 写出可审核的 Judge

### Rubric 怎样把“回答好不好”变成判断标准？

让评审只判一个轴，例如“是否作出有证据支持的退款判断”，并给它**问题、订单与政策证据、候选回答、判定规则**。示意评分合同：

```text
输入: 用户问题 + 已核实订单状态 + 当前政策条款 + 候选答复
输出: {verdict: pass|fail|uncertain, cited_claims: [...], reason: ...}
pass: 不承诺与状态/政策冲突的退款；说明依据和下一步
fail: 承诺不允许的退款、编造订单状态或引用旧版政策
uncertain: 关键证据缺失或相互冲突
```

这里的 `pass|fail|uncertain` 在代码块里作为示意，实际 JSON Schema 应用枚举。让 judge **标出具体主张与证据**，便于人工复核；但理由文本不保证一定真实，仍要与原始 trace 对照。固定被测输入、judge 模型和 rubric 版本，否则分数变化可能来自尺子变了，而不是系统变了。

不要把风险不同的维度压成一个 1–5 分。可以分别判“决策”“证据”“语气”，关键错误单独触发 hard fail。Judge 自身看到的资料范围也要足够：没给订单状态，它不能可靠判断退款资格。

### 多轮对话质量：Judge 应分别判哪些指标？

先选**评测单元**：评最后一轮回复时，给 Judge 截至该轮的用户消息、助手回复、适用政策和已发生的工具结果；评整段对话时，再给每轮状态变化与最终结果。不能只把最后一句拿出来评“是否记住上下文”，也不能把未来的客户反馈喂给当时的回复评分。

下面是客服对话的一套**示例 rubric**，并非行业统一指标。每个维度单独判 `2=满足`、`1=部分满足`、`0=失败`；不适用标 `N/A`，证据不足标 `unknown` 并送人工，不能当通过。锚点要随任务与风险修改。

| 对话质量维度 | 本例 2 分的可观察条件 | 0 分的典型错误 |
| --- | --- | --- |
| 切题 / 有用（relevance, helpfulness） | 回答当前退款问题，并给能执行的下一步 | 绕开退款问题，只重复空泛致歉 |
| 必要信息完整（completeness） | 说明已核实状态、适用限制、下一步；缺条件时明确要补什么 | 漏掉会改变结论的地区或政策条件 |
| 多轮状态一致（context consistency） | 沿用已给订单号和地区；客户纠正状态后更新判断 | 反复索要已提供信息，或继续引用被纠正的旧状态 |
| 有据且正确（grounding / correctness） | 每项关键事实能对应当前订单/政策证据，结论与权威状态一致 | 编造“已退款”或用过期政策承诺退款 |
| 指令与边界遵循（instruction following） | 按客服规则说明权限边界，不泄露其他订单信息 | 遵循客户要求而绕过身份核验或越权承诺 |
| 不确定性处理（uncertainty / clarification） | 缺关键事实时只问必要问题，说明暂不能判断 | 没查订单却自信宣布退款资格 |
| 表达与分寸（clarity / tone） | 对焦虑的客户简洁、尊重地解释限制和下一步 | 生硬推责、冗长套话或用安慰话掩盖不确定性 |

例如客户上一轮已给订单号、地区并说“包裹还在运输中”，系统核实 `in_transit` 和政策 `P-17-v3`。候选答复 A 很礼貌，却说“已为您退款”：表达可得分，但**事实/权限硬失败**；候选 B 正确说明不能走未发货退款，却再次索要订单号、没有下一步：事实通过，状态一致性和完整性较差。Judge 应给出每个维度的分数、触发它的对话片段及证据 ID；订单状态和真实退款写入仍由工具/数据库检查，不靠 Judge 的自信语气。

汇总时先报**各维度通过率** = `该维度得 2 分的可评分对话数 / 该维度适用且证据足够的对话数`，同时列出 `N/A`、`unknown` 和各维度的 `0/1/2` 分布。**整段对话质量通过率** = `所有必需维度达标且无硬失败的对话数 / 可评分对话数`。不要直接平均各维度分数就宣布“质量 80%”：一个错误退款承诺不能被礼貌分抵消。只凭 Judge 得到的是**rubric 评分**，不是用户真实问题解决率；后者见 [Production Evaluation](/docs/evaluation/production-eval)。这类分项 rubric、独立状态检查与人工校准符合 [Anthropic 的对话式 Agent 评测示例](https://www.anthropic.com/engineering/demystifying-evals-for-ai-agents) 和 [OpenAI 的评测实践](https://developers.openai.com/api/docs/guides/evaluation-best-practices)。

## Level 1 · Write an auditable judge

### How does a rubric turn “good answer?” into criteria?

Ask a judge to assess one axis, such as “is the refund decision supported?” Supply the **question, verified order and policy evidence, candidate reply, and criteria**:

```text
Input: question + verified order state + current policy + candidate reply
Output: {verdict: pass|fail|uncertain, cited_claims: [...], reason: ...}
pass: no promise conflicting with state/policy; explain basis and next step
fail: promise forbidden refund, invent status, or cite obsolete policy
uncertain: decisive evidence missing or conflicting
```

`pass|fail|uncertain` is illustrative notation; an implementation should use a real enum schema. Ask for specific claims and evidence so humans can audit decisions, but a judge's explanation can also be wrong. Compare it with source traces. Pin test inputs, judge model, and rubric version; otherwise score changes may reflect a changed ruler.

Do not collapse axes with different risks into one 1–5 score. Grade decision, evidence, and tone separately, and treat critical errors as hard failures. The judge also needs sufficient evidence: without order state it cannot reliably decide eligibility.

3. Why can't new-rubric scores be directly compared to old ones?

</Note>

### Which metrics should a judge use for multi-turn quality?

Define the **evaluation unit** first. To grade the latest assistant turn, supply the user and assistant turns up to that point, applicable policy, and tool results already observed. To grade the whole dialogue, include state changes across turns and the final outcome. A last reply alone cannot reveal context tracking, and later customer feedback must not be leaked into a turn-level grade.

This is an **example task-specific rubric**, not a universal metric standard. Score each dimension separately as `2=met`, `1=partly met`, or `0=failed`. Use `N/A` when the dimension does not apply and `unknown` with human review when evidence is insufficient. Adapt the anchors to the task and risk.

| Conversation-quality dimension | Observable 2-point behavior here | Typical 0-point failure |
| --- | --- | --- |
| Relevance / helpfulness | Answers the current refund question with an actionable next step | Avoids the question with generic apologies |
| Completeness | Explains verified state, applicable constraint, and next step; asks for missing decisive facts | Omits a region or policy condition that changes the decision |
| Context consistency | Uses the supplied order and region; updates the decision after a correction | Reasks for known facts or keeps relying on corrected stale state |
| Grounding / correctness | Key claims match current order and policy evidence; decision matches authoritative state | Invents “refund completed” or promises a refund under obsolete policy |
| Instruction following / boundaries | Explains authority limits under support rules; does not expose other orders | Bypasses identity verification or promises an unauthorized action on user request |
| Uncertainty / clarification | Asks only for decisive missing facts and says a decision is pending | Declares eligibility confidently without checking the order |
| Clarity / tone | Explains limits and next steps concisely and respectfully to a worried customer | Blames the customer, pads with boilerplate, or hides uncertainty behind reassurance |

Suppose the customer already supplied order ID and region and said the package is in transit; the system verified `in_transit` and policy `P-17-v3`. Candidate A sounds empathetic but says “I refunded you”: communication may score well, but **facts/authority hard-fail**. Candidate B correctly rejects the unshipped refund path but asks for the order ID again and gives no next step: factuality passes while context consistency and completeness suffer. Require a score per dimension, the triggering dialogue span, and evidence IDs. Verify order state and actual refund writes with tools or database checks, not the judge's confident wording.

Report a **per-dimension pass rate** = `score-2 conversations / applicable conversations with sufficient evidence`, alongside `N/A`, `unknown`, and the `0/1/2` distribution. A **whole-dialogue quality pass rate** = `conversations meeting every required dimension with no hard failure / scoreable conversations`. Do not average dimension scores and call it “80% quality”: politeness cannot offset a false refund promise. A judge produces a **rubric grade**, not a verified customer-resolution rate; the latter belongs in [Production Evaluation](/docs/evaluation/production-eval). The mix of dimension-specific rubrics, independent state checks, and human calibration follows [Anthropic's conversational-agent eval example](https://www.anthropic.com/engineering/demystifying-evals-for-ai-agents) and [OpenAI's eval guidance](https://developers.openai.com/api/docs/guides/evaluation-best-practices).

## Level 2 · 成对比较与偏差

### A 比 B 好，怎样问得更公平？

若 A 与 B 都答对退款资格，但措辞和解释不同，成对比较让 judge 在**相同问题、证据与标准**下选更好的答案。它通常比“各打一个抽象 1–5 分”更容易定义差异，但不是天然无偏。给匿名的 A/B，交换展示顺序，再观察是否翻转；允许 **平局** 和“证据不足”。

例：A 用 30 字给对决策但缺下一步；B 用 120 字给对决策并清楚列下一步。若 rubric 看重完整性，B 可能胜出；若 B 额外编造“免费退货”，应判失败，不因更长、更自信而获胜。LLM judge 可能有**位置、冗长、风格或同系列模型偏好**；研究已观察到这些偏差，具体大小依模型与任务变化。[MT-Bench/Chatbot Arena 研究](https://arxiv.org/abs/2306.05685)

对于“是否发生越权写入”这类事实，别用成对偏好来决定。成对比较适合难以给绝对分的表达质量或整体偏好，但事实与安全条件应由独立确定性检查优先覆盖。

**偏好胜率**也要写清分母。假设同一批 20 段对话、相同证据与预算下，A 胜 8、B 胜 7、平局 5，则 A 的严格胜率为 `8/20=40%`；只算非平局时是 `8/15≈53.3%`；若事先约定平局各得半分，则是 `(8+0.5×5)/20=52.5%`。三者不是同一指标。报告胜/负/平局原始计数、平局处理规则，以及交换位置后有多少裁决翻转；胜率不能覆盖事实硬失败。

## Level 2 · Pairwise comparison and bias

### How do you ask whether A is better than B fairly?

If both A and B make the correct refund decision but differ in explanation, pairwise comparison asks a judge to choose under the **same question, evidence, and criteria**. It can be easier to discriminate than assigning two abstract 1–5 scores, but is not bias-free. Blind the names, swap display order, and allow **ties** or “insufficient evidence.”

Example: A gets the decision right in 30 words but omits the next step; B explains it in 120 words. B may win for completeness. If B also invents “free returns,” it should fail despite length and confidence. LLM judges can exhibit **position, verbosity, style, and model-family biases**; their sizes vary by task and model. [MT-Bench/Chatbot Arena study](https://arxiv.org/abs/2306.05685)

Do not use preference voting to establish whether an unauthorized write occurred. Pairwise grading suits expression quality or overall preference, while factual and safety constraints deserve direct checks.

Define the denominator of **pairwise win rate**. On 20 matched dialogues under the same evidence and budget, suppose A wins 8, B wins 7, and 5 tie. A's strict win rate is `8/20=40%`; among non-ties it is `8/15≈53.3%`; with a predeclared half point per tie it is `(8+0.5×5)/20=52.5%`. These are different metrics. Report the raw win/loss/tie counts, tie convention, and how many judgments flip after swapping positions. A preference win cannot override a factual hard failure.

## Level 3 · 用人工标签校准 Judge

### 如何量化“Judge 大体同意人工”？

在**10 个教学样本**上，专家确认 6 个通过、4 个失败。Judge 的混淆表如下（“正”=应通过）：

| | 人工通过 | 人工失败 |
| --- | ---: | ---: |
| Judge 通过 | 5 | 2 |
| Judge 失败 | 1 | 2 |

一致数为 `(5+2)/10 = 70%`；更关键的是 **false pass = 2/4 = 50% 的人工失败被放过**。这么小的样本只用于手算，不能稳定估计总体表现。若两条假通过都是越权退款，judge 不适合作为唯一发布门槛。

复用 [Fundamentals 的混淆矩阵](/docs/evaluation/fundamentals)，这里把**「发现失败」定义为正类**：TP=2（人工失败、Judge 判失败），FP=1（人工通过、Judge 错判失败），FN=2（人工失败、Judge 放过），TN=5。于是 Judge 的失败检测 **Precision=`2/(2+1)=66.7%`，Recall=`2/(2+2)=50%`，F1=`2×2/(2×2+1+2)≈57.1%`**。50% 的失败检测 Recall 正好对应上面的 50% false pass：两个值共用 4 条人工失败作分母。面试里要明确正类；若把「通过」改作正类，同一张表会产生另一组 Precision/Recall。

校准流程：① 由业务专家标注分层样本并处理分歧；② 将 judge 判定与人工逐 case 对照，特别查看 false pass；③ 改进 rubric、证据输入、阈值或改为确定性检查；④ 在**未用于调 judge 的样本**上重测；⑤ 版本更新后持续抽样审计。也要检查不同语言、订单状态和较长回答是否有系统偏差。

<Note type="danger" title="不要让 Judge 给自己背书">

用同一个 judge 自动造标签、调 rubric、再报告与这些标签“一致”，会产生循环验证。高后果判断需要独立人或权威系统作对照。

</Note>

## Level 3 · Calibrate against people

### How do you quantify “the judge mostly agrees with experts”?

On **10 teaching cases**, experts mark 6 pass and 4 fail. The judge confusion table is:

| | Human pass | Human fail |
| --- | ---: | ---: |
| Judge pass | 5 | 2 |
| Judge fail | 1 | 2 |

Agreement is `(5+2)/10 = 70%`. More concerning, **false-pass rate among human failures is 2/4 = 50%**. Ten cases illustrate the arithmetic, not a stable population estimate. If the two false passes are unauthorized refunds, the judge cannot be the only release gate.

Apply the [Fundamentals confusion matrix](/docs/evaluation/fundamentals) with **“detect a failure” as the positive class**: TP=2 (human fail, judge fail), FP=1 (human pass, judge fail), FN=2 (human fail, judge pass), TN=5. The judge's failure-detection **Precision=`2/(2+1)=66.7%`, Recall=`2/(2+2)=50%`, and F1=`2×2/(2×2+1+2)≈57.1%`**. Its 50% failure Recall corresponds to the 50% false-pass rate above: both divide by the four human failures. Name the positive class in an interview; treating “pass” as positive gives different Precision and Recall from the same table.

Calibrate by ① expert-labeling sliced cases and resolving disputes; ② reviewing case-level disagreements, especially false passes; ③ changing rubric, evidence, threshold, or using deterministic checks; ④ retesting on cases **not used to tune the judge**; and ⑤ sampling audits after version changes. Look for systematic errors across languages, order states, and answer lengths.

<Note type="danger" title="Do not let a judge validate itself">

Using one judge to create labels, tune its rubric, and report “agreement” with those labels is circular. High-consequence decisions need independent people or authoritative systems.

</Note>
