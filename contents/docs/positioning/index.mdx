## 目标岗位画像

最适合的定位是 **Production LLM / AI Engineer**：能理解模型原理，能构建 RAG / Agent，能设计 AI 系统，能做评测、优化和部署，并且能解释真实生产环境里的取舍。

这和现有经历匹配：Gemini / LLM API、RAG、LangGraph / ADK、Tool calling、Multi-agent、MongoDB / BigQuery、FastAPI / Streamlit、Docker / 部署、延迟优化、评测、企业级 AI。

| 项 | 当前定稿 |
| --- | --- |
| 主投 | Production LLM Engineer / AI Engineer / Applied AI Engineer |
| 次投 | ML Engineer / Applied Scientist / Research Engineer / AI Platform Engineer（JD 匹配再投） |
| 经验锚点 | 3–5 年 |
| 方向 | Agentic AI、RAG、Context Engineering、评测、生产级 LLM 系统 |
| 级别 | 中级（Intermediate / Mid-level） |
| 地点 | 多伦多 / 远程 / 混合办公；美国远程视签证与 JD 而定 |
| 公司类型 | 大厂 / AI 创业公司 / 企业级 AI / 咨询 |
| 不做 | 泛化 Data Scientist；传统 ML Engineer 包装；纯 LLM Research Engineer |

不要按 Research Engineer 路线把 40% 时间砸在 Transformer 数学上。深度模型训练和传统机器学习够用即可。知识优先级见 [准备手册](/docs/overview)。

一句话对外定位：

> 我端到端地构建生产级 LLM 系统——从模型 / 推理优化，到 agent 编排、检索、工具、后端基础设施、评测和部署。

英文原稿：

> I build production-grade LLM systems end-to-end — from model/inference optimization to agent orchestration, retrieval, tools, backend infrastructure, evaluation, and deployment.

## 自我介绍

三个版本都要能脱稿。定稿的对外叙述在 [个人介绍](/resume/about)；这里只练面试开口。

### 30 秒

> 我是多伦多的一名 LLM Engineer，做生产级 agentic 系统——RAG、tool calling、评测和部署。最近主要在 Gemini 上做 multi-agent 工作流，接的是 BigQuery 里的企业数据。

英文原稿：

> I'm an LLM Engineer in Toronto. I build production agentic systems — RAG, tool calling, evaluation, and deployment. Recently that's been multi-agent workflows on Gemini with enterprise data in BigQuery.

### 60 秒

> 我目前在 Unilever 做 LLM Engineer，为企业场景构建生产级 agentic AI 系统。工作覆盖整个 LLM 应用栈——agent 编排、RAG、tool calling、企业数据集成、评测和部署。比如，我用 Gemini、Google ADK 和 LangGraph 做过 multi-agent 系统，让 agent 把网络调研和 BigQuery 分析结合起来。在这之前，我做过 RAG 系统、实时语音 AI 和深度学习系统。我也有用 QLoRA 和 DeepSpeed 做 LLM fine-tuning、用 vLLM 做推理优化的实际经验。我的重点是 LLM 系统和生产级 AI 工程的交叉地带。

英文原稿：

> I currently work as an LLM Engineer at Unilever, where I build production-grade agentic AI systems for enterprise use cases. My work spans the full LLM application stack — agent orchestration, RAG, tool calling, enterprise data integration, evaluation, and deployment. For example, I've built multi-agent systems using Gemini, Google ADK and LangGraph, where agents combine web research with BigQuery analytics. Before that, I worked on RAG systems, real-time voice AI, and deep learning systems. I also have hands-on experience with LLM fine-tuning using QLoRA and DeepSpeed, and inference optimization with vLLM. My focus is the intersection of LLM systems and production AI engineering.

### 2 分钟

60 秒版之后接 **一个** 代表项目：Negotiation Practice（全栈实时）或 Tariff Agent（multi-agent + 企业数据）。按「做了什么 → 为什么 → 你负责哪部分 → 一个量化结果」讲。停下，等面试官追问。不要把五个项目一次倒完。

背熟后，任意追问都应接到 [项目深挖](/docs/projects) 的 Tier 1 子页。

## Self-introduction

All three versions need to work without notes. The polished public version lives in [About](/resume/about); this page is only for practicing the interview opener.

### 30 seconds

> I'm an LLM Engineer in Toronto. I build production agentic systems — RAG, tool calling, evaluation, and deployment. Recently that's been multi-agent workflows on Gemini with enterprise data in BigQuery.

### 60 seconds

> I currently work as an LLM Engineer at Unilever, where I build production-grade agentic AI systems for enterprise use cases. My work spans the full LLM application stack — agent orchestration, RAG, tool calling, enterprise data integration, evaluation, and deployment. For example, I've built multi-agent systems using Gemini, Google ADK and LangGraph, where agents combine web research with BigQuery analytics. Before that, I worked on RAG systems, real-time voice AI, and deep learning systems. I also have hands-on experience with LLM fine-tuning using QLoRA and DeepSpeed, and inference optimization with vLLM. My focus is the intersection of LLM systems and production AI engineering.

### 2 minutes

After the 60-second version, go into **one** flagship: Negotiation Practice (full-stack, real-time) or Tariff Agent (multi-agent + enterprise data). Walk through What → Why → what you did → one quantified result. Then stop and let the interviewer dig in. Don't dump all five projects at once.

Once this is memorized, any follow-up should lead into a Tier 1 page in [Projects](/docs/projects).
