这一块不花很多时间，但必须先定。它决定后面学什么、简历强调什么、项目讲多深。

薪资数字、谈薪策略只放在本地或 [投递](/companies/overview)，不上这篇公开页。

## Target Job Profile

| 项 | 当前定稿 |
| --- | --- |
| Primary | LLM Engineer / AI Engineer / Applied AI Engineer |
| Secondary | ML Engineer / Applied Scientist / Research Engineer（JD 匹配再投） |
| 经验锚点 | 3–5 years |
| Focus | Agentic AI, RAG, LLM applications, inference, evaluation |
| Level | Intermediate / Mid-level |
| Location | Toronto / Remote / Hybrid；US remote 视签证与 JD |
| 公司类型 | Big Tech / AI startup / Enterprise AI / Consulting |
| 不做 | 泛化 Data Scientist；传统 ML Engineer 包装 |

一句话对外定位：

> I build production-grade LLM systems end-to-end — from inference and retrieval to agent orchestration, evaluation, and deployment.

## 职业叙事

面试开场按这条线讲，不要跳成「我做过一些 ChatGPT 项目」。

```
ML / Deep Learning
       ↓
LLM Fine-tuning
       ↓
RAG / Agents
       ↓
Production LLM Systems
       ↓
Enterprise Agentic AI
```

## Self Introduction

三个版本都要能脱稿。定稿对外叙述在 [个人介绍](/resume/about)；这里只练面试开口。

### 30 秒

> I'm an LLM Engineer in Toronto. I build production agentic systems — RAG, tool calling, evaluation, and deployment. Recently that's been multi-agent workflows on Gemini with enterprise data in BigQuery.

### 60 秒

> I currently work as an LLM Engineer at Unilever, where I build production-grade agentic AI systems for enterprise use cases. My work spans the full LLM application stack — agent orchestration, RAG, tool calling, enterprise data integration, evaluation, and deployment. For example, I've built multi-agent systems using Gemini, Google ADK and LangGraph, where agents combine web research with BigQuery analytics. Before that, I worked on RAG systems, real-time voice AI, and deep learning systems. I also have hands-on experience with LLM fine-tuning using QLoRA and DeepSpeed, and inference optimization with vLLM. My focus is the intersection of LLM systems and production AI engineering.

### 2 分钟

60 秒版之后接 **一个** flagship：Negotiation Practice（全栈实时）或 Tariff Agent（multi-agent + 企业数据）。讲 What → Why → 你做了什么 → 一个量化结果。停，等面试官追问。不要把五个项目一次倒完。

背熟后，任意追问应接到 [项目深挖](/docs/projects) 的 Tier 1 子页。
