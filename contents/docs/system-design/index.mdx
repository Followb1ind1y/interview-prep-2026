概念在 LLM / RAG / Agent。这里练的是 **开口框架 + 六个维度**。每做完一道白板题，把权衡写进对应维度页，不要在总览堆全文。

## 开口框架

<Step>
  <StepItem title="澄清">
    用户量、读写比、延迟、一致性、是否要登录 / 搜索 / 实时 / 流式。
  </StepItem>
  <StepItem title="估算">
    QPS、存储、带宽，以及 **token / 成本**。先给数量级，再画图。
  </StepItem>
  <StepItem title="草图">
    Client → API Gateway → Orchestration / Retriever / Model → Storage / Cache / Queue。
  </StepItem>
  <StepItem title="深挖">
    选 1–2 个难点：延迟、幻觉、工具失败、评测、成本。
  </StepItem>
</Step>

## 本专栏计划（先练这 6 题）

| 题 | 优先写进 |
| --- | --- |
| Production RAG | Architecture + Evaluation 意识 |
| ChatGPT-like app | Architecture + Cost |
| Enterprise business Q&A Agent | Reliability |
| Real-time Voice AI | Latency |
| LLM Evaluation Platform | Observability |
| Negotiation Practice（30–45 min） | Architecture + Latency |

传统 Shortener / Feed 只在 JD 明显偏通用后端时再补。
