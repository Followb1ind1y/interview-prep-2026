[Attention](/docs/llm/attention) is the heart of a Transformer, but attention alone doesn't make an LLM: it has no sense of word order, no non-linearity, and a deep stack of it won't train. A Transformer assembles attention with a few other parts — positional encoding, FFN, residual connections, normalization — into a structure you can stack a hundred layers deep.

The goal here: **draw the full path a token takes from input to being sampled, and explain what breaks if each part is removed.** How attention computes internally lives on the Attention page; here it's a black box.

## Level 1 · 整体结构

### 一个 token 从输入到被生成出来，要经过哪些步骤？

用 GPT-2 small 的真实配置走一遍（12 层、d_model = 768、词表 50,257、上下文 1,024），假设输入是一句 5 个 token 的话，batch 为 1：

```
① token ids                         [1, 5]            来自 tokenizer，整数
② token embedding（查表）            [1, 5, 768]       每个 id 取词表矩阵的一行
③ + 位置信息                          [1, 5, 768]       让模型知道谁在前谁在后
④ × 12 个 Transformer block          [1, 5, 768]       形状始终不变，内容越来越「懂上下文」
     每个 block 里：
       x = x + Attention(Norm(x))    token 之间交换信息
       x = x + FFN(Norm(x))          每个 token 自己加工信息
⑤ 最后一次 Norm                       [1, 5, 768]
⑥ LM head（线性层）                  [1, 5, 50257]     每个位置对整个词表打分 = logits
⑦ 只取最后一个位置                    [1, 50257]        它负责预测「下一个 token」
⑧ softmax → 采样                      1 个新 token id
⑨ 把新 token 拼到输入末尾，回到 ①（有 KV cache 时只算新 token）
```

几个值得注意的点：

- **从 ② 到 ⑤，形状一直是 `[batch, 长度, 768]`**。每个 block 输入输出同形状，所以才能随便堆 12 层、32 层、80 层
- **Attention 是唯一让 token 之间交流的地方**，FFN、Norm 都是每个 token 各自算
- **第 ⑥ 步每个位置都会出 logits**。训练时每个位置都拿来算 loss（第 1 个位置预测第 2 个 token……），一句话同时产生 n 个训练信号；推理时只用最后一个

<Note title="Embedding 表和 LM head 常常是同一个矩阵">

第 ② 步的 embedding 矩阵是 `[50257, 768]`，第 ⑥ 步把 768 维变回 50,257 个分数的矩阵正好是它的转置形状。GPT-2 就让两者共用参数（weight tying），省下约 3,860 万个参数。LLaMA 等更大的模型通常不共用。

</Note>

### Encoder-only、Decoder-only、Encoder-Decoder 有什么区别？

三者都用同样的 block，**区别在 attention 能看哪些位置，以及有没有 cross-attention**：

| | 代表模型 | Attention 能看哪 | 训练目标 | 擅长 |
| --- | --- | --- | --- | --- |
| Encoder-only | BERT、RoBERTa | 双向：每个 token 看整句 | 遮住一些词，让模型填回来 | 理解：分类、抽取、生成 embedding |
| **Decoder-only** | GPT 系、LLaMA、Claude | 单向：只看前面（causal mask） | 预测下一个 token | 生成：对话、写作、代码 |
| Encoder-Decoder | 原始 Transformer、T5 | 编码器双向；解码器单向 + cross-attention 看编码器输出 | 输入序列 → 输出序列 | 翻译、摘要这类输入输出明确分开的任务 |

用一句话记：**encoder 负责「读懂」，decoder 负责「接着写」**，encoder-decoder 是先读完原文再写译文。

<Note title="为什么 BERT 不能直接拿来生成文本" type="tip">

BERT 训练时每个词都能看到左右两边，从来没学过「只看左边、猜下一个」。让它从左往右生成，训练和使用的条件对不上。反过来，这种双向理解正是它适合做 embedding 的原因——很多 RAG 用的 embedding 模型就是 encoder-only 结构，见 [Embedding](/docs/rag/embedding)。

</Note>

### 为什么现在的 LLM 几乎都是 decoder-only？

不是因为另外两种「做不到」，而是 decoder-only 在「做大、做通用」这件事上最省事：

1. **训练数据不用加工。** 任意一段文本都是训练样本，每个位置都在预测下一个 token，一句 n 个 token 的话产生 n 个训练信号。Encoder-decoder 需要切出「输入 / 输出」两段
2. **一种结构覆盖所有任务。** 翻译、问答、分类都能写成「给一段 prompt，接着往下写」，任务差异全部变成 prompt 的差异
3. **生成时天然能用 KV cache。** Causal mask 保证前面 token 的 K、V 不会变，缓存复用（见 [Attention](/docs/llm/attention) Level 3）
4. **结构最简单，堆大最直接。** 只有一种 block，没有编码器解码器之间的配比问题

<Note title="别把 decoder-only 说成「全面更强」" type="warning">

T5、Flan-T5 这类 encoder-decoder 在同等规模下的翻译、摘要表现并不差，BERT 系在分类和 embedding 上至今仍然常用。decoder-only 胜出主要是「规模化 + 通用性」上的工程选择。面试里这样说更准确。

</Note>

</Locale>

## Level 1 · Overall structure

### What steps does a token go through from input to being generated?

Walk through it with GPT-2 small's real config (12 layers, d_model = 768, vocabulary 50,257, context 1,024), a 5-token input, batch size 1:

```
① token ids                         [1, 5]            integers from the tokenizer
② token embedding (lookup)          [1, 5, 768]       each id grabs one row of the embedding matrix
③ + position information            [1, 5, 768]       so the model knows what comes before what
④ × 12 Transformer blocks           [1, 5, 768]       shape never changes; content becomes context-aware
     inside each block:
       x = x + Attention(Norm(x))    tokens exchange information
       x = x + FFN(Norm(x))          each token processes its own information
⑤ final Norm                        [1, 5, 768]
⑥ LM head (linear layer)            [1, 5, 50257]     every position scores the whole vocabulary = logits
⑦ keep only the last position       [1, 50257]        it's the one predicting the next token
⑧ softmax → sample                  one new token id
⑨ append the new token and go back to ① (with a KV cache, only the new token is computed)
```

A few things worth noticing:

- **From ② through ⑤ the shape stays `[batch, length, 768]`.** Every block has the same input and output shape, which is exactly why you can stack 12, 32, or 80 of them
- **Attention is the only place tokens talk to each other.** The FFN and Norm operate on each token independently
- **Step ⑥ produces logits at every position.** In training, every position contributes to the loss (position 1 predicts token 2, and so on), so one sentence yields n training signals at once; at inference only the last position is used

<Note title="The embedding table and the LM head are often the same matrix">

The embedding matrix in step ② is `[50257, 768]`, and the matrix in step ⑥ that maps 768 dims back to 50,257 scores has exactly the transposed shape. GPT-2 shares the two (weight tying), saving about 38.6 million parameters. Larger models such as LLaMA usually don't.

</Note>

### How do encoder-only, decoder-only, and encoder-decoder differ?

All three use the same blocks. **The difference is which positions attention may look at, and whether there's cross-attention:**

| | Examples | What attention can see | Training objective | Good at |
| --- | --- | --- | --- | --- |
| Encoder-only | BERT, RoBERTa | bidirectional: every token sees the whole sentence | mask some words, have the model fill them in | understanding: classification, extraction, producing embeddings |
| **Decoder-only** | the GPT family, LLaMA, Claude | one direction: only earlier tokens (causal mask) | predict the next token | generation: chat, writing, code |
| Encoder-decoder | original Transformer, T5 | encoder bidirectional; decoder causal plus cross-attention to the encoder output | input sequence → output sequence | tasks with a clean input/output split, like translation and summarization |

One line to remember: **the encoder reads, the decoder keeps writing.** An encoder-decoder reads the whole source first, then writes the output.

<Note title="Why BERT can't simply be used to generate text" type="tip">

During training every BERT token sees both sides; it never learned "look only left and guess the next word." Asking it to generate left to right mismatches how it was trained. That same bidirectional understanding is why it's good at embeddings — many embedding models used in RAG are encoder-only. See [Embedding](/docs/rag/embedding).

</Note>

### Why is nearly every LLM today decoder-only?

Not because the other two can't do the job, but because decoder-only is the least friction when the goal is big and general-purpose:

1. **Training data needs no preparation.** Any text is a training example, every position predicts the next token, and an n-token sentence yields n training signals. Encoder-decoder needs data split into input and output
2. **One architecture covers every task.** Translation, QA, and classification can all be phrased as "here's a prompt, keep writing," so task differences become prompt differences
3. **Generation gets the KV cache for free.** The causal mask guarantees earlier tokens' K and V never change, so they can be cached and reused (see [Attention](/docs/llm/attention) Level 3)
4. **The simplest structure scales most directly.** One kind of block, no encoder/decoder balance to tune

<Note title="Don't frame decoder-only as strictly better" type="warning">

Encoder-decoder models like T5 and Flan-T5 hold up well on translation and summarization at similar scale, and BERT-style models are still widely used for classification and embeddings. Decoder-only won mainly as an engineering choice for scale and generality — the more accurate way to put it in an interview.

</Note>

## Level 2 · 部件机制

### 为什么 Transformer 需要位置编码？

**因为 attention 本身完全不看顺序。**

回想 [Attention](/docs/llm/attention) 的计算：打分只取决于两个向量的内容（`q·k`），跟它们在第几个位置无关。把输入顺序打乱，每个 token 得到的结果不变，只是输出的顺序跟着换了：

```
"狗 咬 人"  和  "人 咬 狗"
```

如果没有位置信息，这两句话在 attention 眼里是**同一组向量**，模型分不出谁咬谁。RNN 天然按顺序处理所以不需要这个；Transformer 为了并行放弃了顺序处理，就得把位置信息显式加进去。

### 为什么不直接把位置编号 1、2、3 当成位置编码？

三个问题：

1. **数值会失控。** embedding 里的数一般在 ±1 附近，位置 50,000 就是 50,000，一加上去语义信息被完全淹没
2. **归一化也不行。** 改成「位置 / 句长」，同一个第 5 位，在 10 个词的句子里是 0.5，在 100 个词的句子里是 0.05，模型没法学到稳定的含义
3. **没见过的长度无法处理。** 训练最长只见过 1,024，推理遇到 2,000，这个数值模型从来没见过

所以需要一种**数值有界、每个位置唯一、相对距离有规律**的表示。

### Sinusoidal 位置编码怎么算？

原始 Transformer 的方案，用不同频率的 sin / cos 给每个位置生成一个 d_model 维的向量，然后**直接加到 token embedding 上**：

```
PE(pos, 2i)   = sin( pos / 10000^(2i / d) )
PE(pos, 2i+1) = cos( pos / 10000^(2i / d) )
```

用 d = 4 手算前三个位置（第 0、1 维频率是 1，第 2、3 维频率是 1/100）：

```
pos = 0   [sin 0,    cos 0,    sin 0,     cos 0   ]  = [0.000,  1.000, 0.000, 1.000]
pos = 1   [sin 1,    cos 1,    sin 0.01,  cos 0.01]  = [0.841,  0.540, 0.010, 1.000]
pos = 2   [sin 2,    cos 2,    sin 0.02,  cos 0.02]  = [0.909, -0.416, 0.020, 1.000]
```

可以把它想成一个**有很多指针的钟**：

- 低维（前两个数）转得快，像秒针，相邻位置差别很大，负责分辨「近处谁先谁后」
- 高维（后两个数）转得慢，像时针，要隔很远才变，负责分辨「远处的大致位置」
- 所有数都在 [-1, 1] 之间，不会淹没语义；每个位置的「指针组合」都不一样

另外一个好性质：位置 pos + k 的编码可以由位置 pos 的编码经过一个**只和 k 有关的线性变换**得到，模型有机会学到相对距离。

### Learned 位置编码是什么？

更直接的做法：**像词表一样，给每个位置也建一张可学习的表**，训练时一起学。

GPT-2 就是这样：一张 `[1024, 768]` 的位置 embedding 表，共 786,432 个参数，第 pos 个 token 取第 pos 行加到 token embedding 上。

优点是灵活，模型自己决定位置怎么表示；**致命缺点是有硬上限**——表只有 1,024 行，第 1,025 个位置根本没有向量可取。这就是 GPT-2 上下文只能是 1,024 的原因之一。

### RoPE 是怎么做的？为什么现在主流用它？

RoPE（Rotary Position Embedding，旋转位置编码）换了一个思路：**不往 embedding 上加东西，而是在每一层 attention 里，把 Q 和 K 按位置旋转一个角度。**

做法：把 Q、K 向量的维度两两分组，每组看成一个平面上的 2 维向量，第 pos 个 token 就把它旋转 `pos × θ` 角度（不同组的 θ 不同，和 sinusoidal 一样有快有慢）。**V 不旋转。**

它最关键的性质：**旋转之后再做点积，结果只取决于两个 token 的位置差，和绝对位置无关。**

用一个 2 维的例子验证（θ = 0.5，q = [1, 0.5]，k = [0.8, 0.2]，旋转前点积 = 0.9）：

```
q 在位置 3，  k 在位置 1     位置差 2    点积 = 0.3180
q 在位置 10， k 在位置 8     位置差 2    点积 = 0.3180
q 在位置 100，k 在位置 98    位置差 2    点积 = 0.3180
q 在位置 5，  k 在位置 1     位置差 4    点积 = -0.5564
```

位置差相同，打分就完全相同。直觉是：两个向量各转了 mθ 和 nθ，它们之间的**夹角**只差 (m − n)θ，而点积只看夹角。

为什么成为主流（LLaMA 系、Mistral、Qwen 都用）：

- **直接编码相对位置**：attention 打分天然包含「离我多远」，不需要模型自己从绝对位置里推
- **没有可学习参数、没有位置表**，不存在 learned PE 那种「第 1,025 行不存在」的硬上限
- **只作用在 Q、K 上**，不污染 V 和残差流里的语义信息

<Note title="RoPE 和 KV cache 能配合" type="tip">

旋转只取决于 token 自己的位置，所以一个 token 的 K 旋转一次之后就固定了，缓存起来以后不用再改。这也是 RoPE 适合 decoder-only 推理的原因之一。

</Note>

### 上下文是怎么从 8K 扩到 128K 的？什么是长度外推？

**长度外推**指：训练时最长见过 L 个位置，推理时能不能处理比 L 更长的输入。

用 RoPE 的模型也不能直接外推：训练时最长 8K，位置 50,000 对应的旋转角度（尤其是转得慢的那些维度）模型从来没见过，效果会明显崩掉。

实际扩上下文的做法是**「改 RoPE 的频率 + 用长文本继续训练一段」**：

- **Position Interpolation**：把新的长位置按比例「压缩」回训练见过的范围，比如 32K 的位置除以 4 当成 8K 以内的位置用
- **NTK-aware / YaRN**：不同频率区别对待——转得快的维度（管近距离）基本不动，转得慢的维度（管远距离）才拉伸，近处的分辨率不受损
- **调大 RoPE base**：LLaMA 2 的 base 是 10,000，LLaMA 3 调到 500,000，让慢维度转得更慢、覆盖更长距离

LLaMA 3.1 从 8K 扩到 128K，就是在 RoPE 上做了频率缩放，再用长文本数据继续预训练。

<Note title="别说「RoPE / 相对位置编码天然支持任意长度外推」" type="danger">

RoPE 的点积只依赖相对位置，但**模型从没见过的旋转角度依然是分布外的**，直接超出训练长度效果会明显下降。能扩到 128K 靠的是频率缩放加长文本继续训练，不是 RoPE 自带的。

</Note>

</Locale>

### 残差连接解决了什么？

残差连接就是 block 里那个 `x = x + F(x)`：**子层（attention 或 FFN）只负责算一个「增量」，原始输入直接绕过去加回来。**

它解决的是**深层网络训不动**。反向传播时梯度要从最后一层一路乘回第一层：

```
没有残差：每层梯度乘一个系数，假设都是 0.9
          80 层之后 = 0.9^80 ≈ 0.0002    ← 前面的层几乎收不到梯度

有残差：  y = x + F(x)，对 x 求导 = 1 + F'(x)
          那个「1」让梯度可以沿着加法这条路原样传回去，不管 F 学成什么样
```

所以残差不是锦上添花，而是 Transformer 能堆到 80 层（LLaMA 3 70B）的前提。

<Note title="残差流：理解 Transformer 的另一种视角" type="tip">

把那条 `x + … + …` 一路加下来的主干叫做**残差流（residual stream）**：每个 block 都是从残差流里读信息、算完再写回去，形状始终是 `[batch, 长度, d_model]`。这个视角能帮你解释为什么每层输入输出同形状，也是现在可解释性研究常用的框架。

</Note>

### LayerNorm 和 BatchNorm 有什么区别？为什么 Transformer 用 LayerNorm？

两者都是把一堆数减均值、除标准差、再乘一个可学习的缩放 γ 加偏移 β。**区别只在「哪一堆数」**。

假设输入形状 `[batch=2, 长度=5, 维度=4]`，一共 10 个 token，每个 4 维：

```
LayerNorm   对每个 token 单独归一化：用这 1 个 token 自己的 4 个数算均值和方差
BatchNorm   对每个维度单独归一化：用这个维度上全 batch 10 个 token 的数算均值和方差
```

LayerNorm 手算一个 token，x = [2, 4, 6]：

```
均值 = 4
方差 = ((2-4)² + (4-4)² + (6-4)²) / 3 = 2.667，标准差 = 1.633
归一化 = [(2-4)/1.633, 0, (6-4)/1.633] = [-1.225, 0, 1.225]
再乘 γ、加 β（训练中学出来）
```

Transformer 不用 BatchNorm 的原因：

- **依赖 batch 里的其他样本**：一个 token 的结果会随同 batch 里别的句子变化；推理时 batch 常常是 1，统计量和训练时对不上
- **变长序列和 padding**：句子长短不一，补的 `<pad>` 会混进 batch 的均值方差
- **自回归生成**：一次只来一个新 token，没法对「整个 batch 整个序列」求统计量

LayerNorm 只看 token 自己，这三个问题都不存在。

### Pre-LN 和 Post-LN 有什么区别？

区别就是 **Norm 放在子层前面还是残差相加之后**：

```
Post-LN（原始 Transformer、BERT）    x = Norm( x + F(x) )
Pre-LN （GPT-2 起、LLaMA）            x = x + F( Norm(x) )
```

看出差别了吗？Post-LN 的 Norm 压在残差主干上，每一层梯度都要穿过一次 Norm；Pre-LN 的主干是干净的 `x + …`，Norm 只在支路里。

| | Post-LN | Pre-LN |
| --- | --- | --- |
| 残差主干 | 每层被 Norm 打断 | 纯加法直通 |
| 深层训练 | 不稳定，需要仔细的学习率 warmup | 稳定，堆深层容易 |
| 最终效果 | 训练成功时有时略好 | 通常略差一点点，但换来稳定 |
| 额外要求 | 无 | 最后一层之后要补一个 Norm（数据流里的第 ⑤ 步） |

现在的大模型几乎都是 Pre-LN：规模大了以后，「训得稳」比那一点点效果差距重要得多。

### 什么是 RMSNorm？

LayerNorm 的简化版，LLaMA、Mistral 都用它：**不减均值，也不加偏移 β，只除以均方根（RMS）。**

```
RMS(x) = √( (x₁² + x₂² + … + x_d²) / d )
RMSNorm(x) = x / RMS(x) × γ
```

同样 x = [2, 4, 6]：

```
RMS = √((4 + 16 + 36) / 3) = √18.67 = 4.320
RMSNorm = [2/4.320, 4/4.320, 6/4.320] = [0.463, 0.926, 1.389]
```

少了求均值这一步，计算更省，实践中效果和 LayerNorm 基本一样。在要跑成千上万次 Norm 的大模型里，省下来的这点计算是值得的。

### FFN 是什么结构？为什么要先升维再降维？

FFN（前馈网络）是 block 里的第二个子层，**对每个 token 单独做一次两层 MLP**，所有位置共用同一套参数：

```
FFN(x) = W₂ · 激活函数( W₁ · x )

GPT-2 small:  768 维 → W₁ → 3,072 维 → GELU → W₂ → 768 维
```

中间层通常是 d_model 的 4 倍。它的作用可以和 attention 对照着记：

| | Attention | FFN |
| --- | --- | --- |
| 在哪些 token 之间 | token 之间交换信息 | 每个 token 自己算，不看别人 |
| 做的事 | 从上下文里「取」信息 | 对取到的信息做非线性加工 |
| 参数占比（每层） | 约 1/3（4 · d²） | 约 2/3（8 · d²） |

**为什么升维：** 在更高维的空间里，非线性激活能表达的组合多得多，然后再压回 d_model 维放回残差流。有研究认为模型学到的大量「事实性知识」主要存在 FFN 的参数里。

用 GPT-2 small 算一下每层的参数：FFN 约 472 万，attention 约 236 万，正好 2 : 1。

### 激活函数为什么从 ReLU 换成 GELU、SwiGLU？

**ReLU** `max(0, x)` 把所有负数砍成 0。问题是：一个神经元如果输入一直是负的，输出永远是 0、梯度也永远是 0，再也学不回来（「死神经元」）。

**GELU**（GPT-2、BERT 用）是平滑版：大的正数基本原样通过，大的负数接近 0，**0 附近的小负数会留下一部分**：

```
x       ReLU     GELU
1.0     1.0      0.841
-0.1    0        -0.046
-1.0    0        -0.159
```

负数区间仍有梯度，训练更平滑。

**SwiGLU**（LLaMA、Mistral 用）再进一步：用三个矩阵，其中一路当「门」去控制另一路能通过多少。代价是多了一个矩阵，为了让总参数量和普通 FFN 持平，中间维度从 4 倍缩到约 8/3 倍：

```
LLaMA 2 7B:  d_model = 4096
             标准 FFN 会是 4 × 4096 = 16,384
             SwiGLU 取 ⅔ × 16,384 ≈ 10,923，向上取整到 11,008
```

<Note title="面试里 11008 这种「奇怪的数」值得能解释" type="tip">

看到 LLaMA 的 `intermediate_size: 11008` 时能说出「SwiGLU 多一个矩阵，所以中间维度取 ⅔ × 4d 保持参数量不变，再对齐到方便硬件计算的倍数」，比背出结构图更能体现你真读过模型配置。

</Note>

</Locale>

## Level 2 · How the parts work

### Why does a Transformer need positional encoding?

**Because attention itself ignores order completely.**

Recall how [Attention](/docs/llm/attention) computes: a score depends only on the contents of two vectors (`q·k`), not on where they sit. Shuffle the input and each token gets the same result; the outputs just come out in shuffled order:

```
"dog bites man"  and  "man bites dog"
```

Without position information, attention sees these as **the same set of vectors** and can't tell who bit whom. An RNN processes in order, so it gets position for free; a Transformer gave up sequential processing to run in parallel, so position has to be injected explicitly.

### Why not just use the position index 1, 2, 3 as the encoding?

Three problems:

1. **The values blow up.** Embedding values sit around ±1; position 50,000 is 50,000, and adding it drowns out the meaning entirely
2. **Normalizing doesn't fix it.** Use "position / length" and the 5th position is 0.5 in a 10-word sentence but 0.05 in a 100-word one, so the model can't learn a stable meaning
3. **Unseen lengths break.** If training never went past 1,024 and inference hits 2,000, that value is completely new to the model

What's needed is a representation that's **bounded, unique per position, and regular in relative distance**.

### How is sinusoidal positional encoding computed?

The original Transformer's scheme: sin and cos at different frequencies produce a d_model-dimensional vector per position, which is **added directly to the token embedding**:

```
PE(pos, 2i)   = sin( pos / 10000^(2i / d) )
PE(pos, 2i+1) = cos( pos / 10000^(2i / d) )
```

Hand-compute the first three positions with d = 4 (dims 0–1 use frequency 1, dims 2–3 use 1/100):

```
pos = 0   [sin 0,    cos 0,    sin 0,     cos 0   ]  = [0.000,  1.000, 0.000, 1.000]
pos = 1   [sin 1,    cos 1,    sin 0.01,  cos 0.01]  = [0.841,  0.540, 0.010, 1.000]
pos = 2   [sin 2,    cos 2,    sin 0.02,  cos 0.02]  = [0.909, -0.416, 0.020, 1.000]
```

Think of it as **a clock with many hands**:

- Low dimensions (the first two numbers) spin fast, like a second hand — adjacent positions differ a lot, which resolves nearby order
- High dimensions (the last two) spin slowly, like an hour hand — they change only over long distances, which resolves rough far-away position
- Every value stays in [-1, 1], so meaning isn't drowned out, and every position gets a unique combination of hands

One more useful property: the encoding at pos + k is a **linear transformation of the encoding at pos that depends only on k**, which gives the model a chance to learn relative distance.

### What is learned positional encoding?

The more direct approach: **give positions their own learnable table, just like the vocabulary**, trained along with everything else.

That's what GPT-2 does: a `[1024, 768]` position embedding table with 786,432 parameters; token pos takes row pos and adds it to its token embedding.

It's flexible — the model decides how to represent position — but **it has a hard ceiling**: the table has 1,024 rows, so position 1,025 has no vector at all. That's one reason GPT-2's context is capped at 1,024.

### How does RoPE work, and why is it the default now?

RoPE (Rotary Position Embedding) takes a different route: **nothing is added to the embedding; instead, inside every attention layer, Q and K are rotated by an angle that depends on position.**

The mechanics: split the dimensions of Q and K into pairs, treat each pair as a 2D vector in a plane, and rotate the vector for token pos by `pos × θ` (each pair has its own θ, fast to slow, like sinusoidal). **V is not rotated.**

The key property: **after rotation, the dot product depends only on the distance between the two tokens, not on their absolute positions.**

Check it with a 2D example (θ = 0.5, q = [1, 0.5], k = [0.8, 0.2], dot product before rotation = 0.9):

```
q at position 3,   k at position 1     distance 2    dot = 0.3180
q at position 10,  k at position 8     distance 2    dot = 0.3180
q at position 100, k at position 98    distance 2    dot = 0.3180
q at position 5,   k at position 1     distance 4    dot = -0.5564
```

Same distance, identical score. The intuition: the vectors rotate by mθ and nθ, so the **angle between them** changes by exactly (m − n)θ, and a dot product only cares about that angle.

Why it became the default (the LLaMA family, Mistral, and Qwen all use it):

- **Relative position is encoded directly** — the attention score inherently reflects "how far from me," so the model doesn't have to infer it from absolute positions
- **No learned parameters and no position table**, so there's no "row 1,025 doesn't exist" ceiling like learned PE
- **It only touches Q and K**, leaving V and the semantic content of the residual stream untouched

<Note title="RoPE works hand in hand with the KV cache" type="tip">

A rotation depends only on a token's own position, so once a token's K is rotated it's fixed and can be cached without ever changing. That's part of why RoPE suits decoder-only inference.

</Note>

### How does context get extended from 8K to 128K? What is length extrapolation?

**Length extrapolation** asks: if training only saw L positions, can the model handle inputs longer than L?

RoPE models can't do this out of the box either. If training stopped at 8K, the rotation angles for position 50,000 — especially in the slow-spinning dimensions — are ones the model has never seen, and quality falls apart.

In practice, context gets extended by **changing RoPE's frequencies plus some continued training on long text**:

- **Position Interpolation**: scale new, longer positions back into the trained range — e.g. divide 32K positions by 4 so they look like positions within 8K
- **NTK-aware / YaRN**: treat frequencies differently — leave the fast dimensions (near-range) mostly alone and stretch only the slow ones (long-range), so nearby resolution isn't lost
- **Raise the RoPE base**: LLaMA 2 uses a base of 10,000; LLaMA 3 raised it to 500,000, making slow dimensions spin even slower and cover longer distances

LLaMA 3.1 went from 8K to 128K by scaling RoPE frequencies and then continuing pretraining on long-context data.

<Note title="Don't say RoPE or relative position encoding extrapolates to any length for free" type="danger">

RoPE's dot product depends only on relative position, but **rotation angles the model never saw are still out of distribution**; going past the training length directly causes a clear quality drop. Reaching 128K takes frequency scaling plus long-context continued training, not something RoPE provides on its own.

</Note>

### What do residual connections solve?

A residual connection is the `x = x + F(x)` inside a block: **the sublayer (attention or FFN) computes only an increment, and the original input bypasses it and gets added back.**

It solves **deep networks that won't train**. During backprop the gradient has to multiply its way from the last layer back to the first:

```
no residual:   each layer multiplies the gradient by a factor, say 0.9
               after 80 layers = 0.9^80 ≈ 0.0002    ← early layers barely get a gradient

with residual: y = x + F(x), derivative with respect to x = 1 + F'(x)
               that "1" lets the gradient flow back unchanged along the addition, whatever F learns
```

So residual connections aren't a nice-to-have; they're what lets a Transformer stack 80 layers (LLaMA 3 70B).

<Note title="The residual stream: another way to see a Transformer" type="tip">

Call the `x + … + …` backbone that runs through every block the **residual stream**: each block reads from it, computes, and writes back, and its shape is always `[batch, length, d_model]`. This view explains why every layer keeps the same shape, and it's the common framing in current interpretability research.

</Note>

### How do LayerNorm and BatchNorm differ, and why do Transformers use LayerNorm?

Both subtract a mean, divide by a standard deviation, then apply a learned scale γ and shift β. **The only difference is which set of numbers they normalize over.**

Take an input of shape `[batch=2, length=5, dims=4]` — 10 tokens, 4 dims each:

```
LayerNorm   normalizes each token on its own: mean and variance over that token's 4 numbers
BatchNorm   normalizes each dimension on its own: mean and variance over that dimension across all 10 tokens in the batch
```

LayerNorm by hand for one token, x = [2, 4, 6]:

```
mean = 4
variance = ((2-4)² + (4-4)² + (6-4)²) / 3 = 2.667, std = 1.633
normalized = [(2-4)/1.633, 0, (6-4)/1.633] = [-1.225, 0, 1.225]
then multiply by γ and add β (both learned)
```

Why Transformers avoid BatchNorm:

- **It depends on other examples in the batch**: a token's output changes with whatever other sentences share its batch, and at inference the batch is often 1, so the statistics don't match training
- **Variable length and padding**: sentences differ in length, and `<pad>` tokens leak into the batch mean and variance
- **Autoregressive generation**: one new token arrives at a time, so there's no "whole batch, whole sequence" to compute statistics over

LayerNorm only looks at the token itself, so none of these problems arise.

### How do Pre-LN and Post-LN differ?

The difference is **whether Norm sits before the sublayer or after the residual addition**:

```
Post-LN (original Transformer, BERT)   x = Norm( x + F(x) )
Pre-LN  (GPT-2 onward, LLaMA)          x = x + F( Norm(x) )
```

See it? In Post-LN the Norm sits on the residual backbone, so the gradient passes through a Norm at every layer. In Pre-LN the backbone is a clean `x + …` and Norm lives only on the branch.

| | Post-LN | Pre-LN |
| --- | --- | --- |
| Residual backbone | interrupted by Norm every layer | a straight chain of additions |
| Deep training | unstable; needs careful learning-rate warmup | stable; easy to stack deep |
| Final quality | sometimes slightly better when it trains successfully | usually a hair worse, in exchange for stability |
| Extra requirement | none | a final Norm after the last block (step ⑤ in the data flow) |

Nearly every large model today is Pre-LN: at scale, training reliably matters far more than that small quality gap.

### What is RMSNorm?

A simplified LayerNorm used by LLaMA and Mistral: **no mean subtraction and no shift β — just divide by the root mean square.**

```
RMS(x) = √( (x₁² + x₂² + … + x_d²) / d )
RMSNorm(x) = x / RMS(x) × γ
```

Same x = [2, 4, 6]:

```
RMS = √((4 + 16 + 36) / 3) = √18.67 = 4.320
RMSNorm = [2/4.320, 4/4.320, 6/4.320] = [0.463, 0.926, 1.389]
```

Skipping the mean saves compute, and in practice quality matches LayerNorm. In a large model that runs Norm an enormous number of times, that saving is worth it.

### What's the FFN's structure, and why expand the dimension and then shrink it?

The FFN (feed-forward network) is the second sublayer in a block: **a two-layer MLP applied to each token independently**, with the same parameters at every position:

```
FFN(x) = W₂ · activation( W₁ · x )

GPT-2 small:  768 dims → W₁ → 3,072 dims → GELU → W₂ → 768 dims
```

The hidden layer is usually 4x d_model. It's easiest to remember next to attention:

| | Attention | FFN |
| --- | --- | --- |
| Between which tokens | exchanges information across tokens | each token on its own, no looking at others |
| What it does | pulls information in from context | processes that information non-linearly |
| Share of parameters (per layer) | about 1/3 (4 · d²) | about 2/3 (8 · d²) |

**Why expand:** in a higher-dimensional space the non-linearity can express far more combinations; the result is then projected back to d_model and written into the residual stream. Some research suggests much of the factual knowledge a model learns lives mainly in FFN parameters.

For GPT-2 small, per layer: about 4.72 million FFN parameters vs. 2.36 million for attention — exactly 2 : 1.

### Why move from ReLU to GELU and SwiGLU?

**ReLU**, `max(0, x)`, cuts every negative value to 0. The problem: if a neuron's input stays negative, its output and gradient are permanently 0 and it can never recover (a "dead neuron").

**GELU** (used by GPT-2 and BERT) is the smooth version: large positives pass through almost unchanged, large negatives go to nearly 0, and **small negatives near 0 partly survive**:

```
x       ReLU     GELU
1.0     1.0      0.841
-0.1    0        -0.046
-1.0    0        -0.159
```

The negative range still has a gradient, so training is smoother.

**SwiGLU** (used by LLaMA and Mistral) goes further: three matrices, one path acting as a gate that controls how much of the other gets through. The extra matrix costs parameters, so to keep the total equal to a standard FFN, the hidden size shrinks from 4x to about 8/3x:

```
LLaMA 2 7B:  d_model = 4096
             a standard FFN would be 4 × 4096 = 16,384
             SwiGLU uses ⅔ × 16,384 ≈ 10,923, rounded up to 11,008
```

<Note title="Be able to explain odd numbers like 11008" type="tip">

When you see LLaMA's `intermediate_size: 11008`, saying "SwiGLU adds a matrix, so the hidden size is ⅔ × 4d to keep parameters constant, then rounded to a hardware-friendly multiple" shows you've actually read model configs — more convincing than reciting the block diagram.

</Note>

## Level 3 · 工程影响

### 参数量怎么估算？

一个标准 block 的参数集中在两处：attention 的 4 个投影矩阵（W_Q、W_K、W_V、W_O，各 d × d）和 FFN 的两个矩阵（d × 4d、4d × d）：

```
每层 ≈ 4d² （attention） + 8d² （FFN） = 12d²
总量 ≈ 12 × 层数 × d²  +  词表大小 × d （embedding）
```

用 GPT-2 small 对账（12 层、d = 768、词表 50,257）：

```
12 个 block        12 × 12 × 768²        ≈ 8,490 万
token embedding    50,257 × 768          ≈ 3,860 万
位置 embedding     1,024 × 768           ≈ 79 万
合计                                      ≈ 1.24 亿      ← 官方 124M，对得上
```

LLaMA 2 7B 用的是 SwiGLU（FFN 3 个矩阵，中间维度 11,008），公式要换成每层 `4d² + 3 × d × 11008`，再加上不共用的 embedding 和 LM head，算出来是 67.4 亿——就是模型卡上写的 6.74B。

<Note title="小模型里 embedding 占比惊人" type="tip">

GPT-2 small 的 1.24 亿参数里，光 token embedding 就占了 31%。这也是 [Tokenization](/docs/llm/tokenization) 里「词表大小的 trade-off」在小模型上格外明显的原因；到 70B 这种规模，embedding 的占比就可以忽略了。

</Note>

### 参数量怎么变成显存和成本？

**推理时，权重显存 = 参数量 × 每个参数的字节数：**

```
              每参数字节    7B 模型权重
fp16 / bf16   2            ≈ 14 GB
int8          1            ≈ 7 GB
int4          0.5          ≈ 3.5 GB
```

但这只是开始。实际要放下的是：

```
推理显存 ≈ 权重 + KV cache + 临时激活
```

KV cache 随上下文长度和并发数增长，长上下文下可能比权重还大（算法见 [Attention](/docs/llm/attention) Level 3）。

**训练显存大得多。** 常用混合精度 + Adam 优化器时，每个参数要存：fp16 权重 2 字节 + fp16 梯度 2 字节 + fp32 主权重 4 字节 + Adam 的两个状态 8 字节 = **16 字节**。7B 模型光这部分就要约 112 GB，还没算激活——所以全量微调 7B 需要多卡，而 LoRA / QLoRA 能在单卡上做（见 [Fine-tuning](/docs/llm/fine-tuning)）。

### 为什么参数量直接决定生成速度？

两个粗略但很好用的规律：

- **计算量**：前向计算一个 token，大约需要 **2 × 参数量** 次浮点运算。7B 模型每个 token 约 140 亿次
- **decode 受显存带宽限制**：每生成一个 token，都要把全部权重从显存读一遍。7B fp16 就是每个 token 读约 14 GB 数据

所以量化能直接提速：int4 权重只有 3.5 GB，每步要读的数据少了 4 倍，decode 的 tokens/sec 会明显上升（同时略微损失质量）。细节见 [Inference](/docs/llm/inference)。

### Logits 怎么变成下一个 token？temperature、top-p 做了什么？

LM head 输出的 logits 是对词表里每个 token 的原始打分，要经过 softmax 变成概率，再按某种策略选出一个。

假设词表只有 3 个候选，logits = [2.0, 1.0, 0.1]：

**Temperature**：softmax 之前先把 logits 除以 T。

```
T = 1.0   softmax([2.0, 1.0, 0.1])  = [0.659, 0.242, 0.099]    原始分布
T = 0.5   softmax([4.0, 2.0, 0.2])  = [0.864, 0.117, 0.019]    更尖锐，更确定
T = 2.0   softmax([1.0, 0.5, 0.05]) = [0.502, 0.304, 0.194]    更平缓，更随机
```

T 越小越接近「永远选最高分」（greedy），T 越大越有创造性、也越容易胡说。和 Attention 页里「除以 √d_k 防止 softmax 饱和」是同一个原理的反向使用。

**Top-k**：只保留分数最高的 k 个候选，其余概率清零后重新归一化。

**Top-p（nucleus）**：按概率从高到低累加，保留**刚好累计到 p** 的那几个。T = 1、p = 0.9 时：

```
0.659 + 0.242 = 0.901 ≥ 0.9  → 保留前 2 个，丢掉 0.099 那个
重新归一化 → [0.731, 0.269]
```

Top-p 比 top-k 灵活：模型很确定时只剩一两个候选，不确定时自动保留更多。

<Note title="temperature = 0 不保证每次输出完全一样" type="warning">

理论上 T = 0 就是 greedy，结果确定。但在线服务里，同一请求可能和不同的其他请求拼进一个 batch，GPU 并行计算的浮点误差会让两个 logits 非常接近的候选偶尔换位，后面生成的内容就分叉了。需要可复现时，要在评测和测试设计里考虑这一点，而不是假设「T = 0 就一定一致」。

</Note>

### 现代 LLM 和原始 Transformer 差在哪？

面试里被问「LLaMA 和原始 Transformer 有什么不同」时，按部件对比最清楚：

| 部件 | 原始 Transformer（2017） | GPT-2（2019） | LLaMA 3（2024） |
| --- | --- | --- | --- |
| 整体结构 | Encoder-Decoder | Decoder-only | Decoder-only |
| 位置编码 | Sinusoidal，加到 embedding | Learned，加到 embedding | RoPE，旋转 Q / K |
| 归一化 | Post-LN，LayerNorm | Pre-LN，LayerNorm | Pre-LN，RMSNorm |
| FFN 激活 | ReLU | GELU | SwiGLU |
| Attention | MHA | MHA | GQA |
| 上下文长度 | — | 1,024 | 8K（3.1 版 128K） |

一句话总结演进方向：**骨架（attention + FFN + 残差 + 归一化）八年没变，每个部件都换成了「训得更稳、推理更省、上下文更长」的版本。**

</Locale>

## Level 3 · Engineering impact

### How do you estimate parameter count?

A standard block's parameters sit in two places: attention's four projections (W_Q, W_K, W_V, W_O, each d × d) and the FFN's two matrices (d × 4d and 4d × d):

```
per layer ≈ 4d² (attention) + 8d² (FFN) = 12d²
total     ≈ 12 × layers × d²  +  vocab size × d (embedding)
```

Check it against GPT-2 small (12 layers, d = 768, vocabulary 50,257):

```
12 blocks          12 × 12 × 768²        ≈ 84.9M
token embedding    50,257 × 768          ≈ 38.6M
position embedding 1,024 × 768           ≈ 0.79M
total                                    ≈ 124M      ← matches the official 124M
```

LLaMA 2 7B uses SwiGLU (three FFN matrices, hidden size 11,008), so each layer is `4d² + 3 × d × 11008`, plus an untied embedding and LM head. That comes to 6.74 billion — exactly the 6.74B on the model card.

<Note title="Embeddings are a surprisingly large share of small models" type="tip">

Of GPT-2 small's 124M parameters, the token embedding alone is 31%. That's why the vocabulary-size trade-off from [Tokenization](/docs/llm/tokenization) bites hardest on small models; at 70B scale the embedding share is negligible.

</Note>

### How does parameter count turn into memory and cost?

**At inference, weight memory = parameters × bytes per parameter:**

```
              bytes/param    7B model weights
fp16 / bf16   2              ≈ 14 GB
int8          1              ≈ 7 GB
int4          0.5            ≈ 3.5 GB
```

That's only the start. What actually has to fit:

```
inference memory ≈ weights + KV cache + transient activations
```

The KV cache grows with context length and concurrency, and at long context it can exceed the weights (the math is in [Attention](/docs/llm/attention) Level 3).

**Training needs far more.** With mixed precision and the Adam optimizer, each parameter carries fp16 weights (2 bytes) + fp16 gradients (2) + fp32 master weights (4) + two Adam states (8) = **16 bytes**. A 7B model needs about 112 GB for that alone, before activations — which is why full fine-tuning a 7B takes multiple GPUs while LoRA / QLoRA fits on one (see [Fine-tuning](/docs/llm/fine-tuning)).

### Why does parameter count directly set generation speed?

Two rough but very useful rules:

- **Compute**: a forward pass for one token takes roughly **2 × parameter count** floating-point operations — about 14 billion per token for a 7B model
- **Decode is memory-bandwidth-bound**: every generated token requires reading all the weights out of memory. For 7B in fp16 that's about 14 GB of data per token

So quantization speeds things up directly: int4 weights are 3.5 GB, a quarter of the data to read each step, so decode tokens/sec rises noticeably (at a small quality cost). Details on [Inference](/docs/llm/inference).

### How do logits become the next token? What do temperature and top-p do?

The LM head's logits are raw scores for every token in the vocabulary. Softmax turns them into probabilities, and a decoding strategy picks one.

Suppose the vocabulary has just 3 candidates with logits = [2.0, 1.0, 0.1]:

**Temperature**: divide the logits by T before softmax.

```
T = 1.0   softmax([2.0, 1.0, 0.1])  = [0.659, 0.242, 0.099]    the original distribution
T = 0.5   softmax([4.0, 2.0, 0.2])  = [0.864, 0.117, 0.019]    sharper, more deterministic
T = 2.0   softmax([1.0, 0.5, 0.05]) = [0.502, 0.304, 0.194]    flatter, more random
```

Lower T approaches "always pick the top score" (greedy); higher T is more creative and more prone to nonsense. It's the same principle as dividing by √d_k to avoid softmax saturation on the Attention page, used in reverse.

**Top-k**: keep only the k highest-scoring candidates, zero out the rest, renormalize.

**Top-p (nucleus)**: add probabilities from highest to lowest and keep the candidates **until the running total reaches p**. With T = 1 and p = 0.9:

```
0.659 + 0.242 = 0.901 ≥ 0.9  → keep the top 2, drop the 0.099 one
renormalize → [0.731, 0.269]
```

Top-p adapts better than top-k: when the model is confident only one or two candidates survive; when it's unsure, more are kept automatically.

<Note title="temperature = 0 doesn't guarantee identical outputs" type="warning">

In theory T = 0 is greedy and deterministic. In a live service, though, the same request can be batched with different other requests, and floating-point differences in parallel GPU math can occasionally swap two candidates with nearly equal logits, after which the generation diverges. When reproducibility matters, account for this in evaluation and test design rather than assuming "T = 0 is always consistent."

</Note>

### How do modern LLMs differ from the original Transformer?

When asked "how does LLaMA differ from the original Transformer," a part-by-part comparison is clearest:

| Part | Original Transformer (2017) | GPT-2 (2019) | LLaMA 3 (2024) |
| --- | --- | --- | --- |
| Overall structure | Encoder-decoder | Decoder-only | Decoder-only |
| Positional encoding | Sinusoidal, added to embedding | Learned, added to embedding | RoPE, rotates Q / K |
| Normalization | Post-LN, LayerNorm | Pre-LN, LayerNorm | Pre-LN, RMSNorm |
| FFN activation | ReLU | GELU | SwiGLU |
| Attention | MHA | MHA | GQA |
| Context length | — | 1,024 | 8K (128K in 3.1) |

The direction of travel in one line: **the skeleton — attention + FFN + residual + normalization — hasn't changed in eight years; every part has been swapped for a version that trains more stably, infers more cheaply, or handles longer context.**

## 陷阱

<Note title="别说「FFN 负责在 token 之间传递信息」" type="danger">

FFN 是对每个 token **单独**算的，完全不看其他位置。整个 Transformer 里只有 attention 让 token 之间交流。把两者的分工说反，面试官会直接怀疑你没真正理解 block 结构。

</Note>

<Note title="别说「残差连接和 LayerNorm 是为了防止过拟合」" type="danger">

它们解决的是**深层网络训不动、训练不稳定**：残差让梯度能传回前面的层，归一化让每层输入的数值范围稳定。防过拟合的是 dropout、权重衰减这类正则化手段。

</Note>

<Note title="参数量不等于推理显存" type="warning">

「7B 模型要 14 GB」只说了 fp16 权重。实际还要加上随上下文和并发增长的 KV cache、以及临时激活；换成 int4 权重又只要 3.5 GB。回答显存问题时要说清精度、上下文长度和并发数。

</Note>

<Note title="位置信息不一定只在输入层加一次" type="warning">

Sinusoidal 和 learned 位置编码是在最开始加到 embedding 上，之后就不再管；RoPE 则是在**每一层**的 attention 里旋转 Q 和 K。说「位置编码就是加在输入上的一个向量」只对老方案成立。

</Note>

</Locale>

<Locale lang="en">

## Traps

<Note title="Don't say the FFN passes information between tokens" type="danger">

The FFN runs on each token **independently** and never looks at other positions. In the whole Transformer, only attention lets tokens communicate. Mixing up the two roles makes an interviewer doubt you understand the block at all.

</Note>

<Note title="Don't say residual connections and LayerNorm prevent overfitting" type="danger">

They address **deep networks that won't train or train unstably**: residuals let gradients reach early layers, and normalization keeps each layer's input range stable. Overfitting is handled by regularization such as dropout and weight decay.

</Note>

<Note title="Parameter count is not inference memory" type="warning">

"A 7B model needs 14 GB" only covers fp16 weights. You still need the KV cache, which grows with context and concurrency, plus transient activations — while int4 weights take just 3.5 GB. A good memory answer states precision, context length, and concurrency.

</Note>

<Note title="Position isn't necessarily added once at the input" type="warning">

Sinusoidal and learned positional encodings are added to the embedding at the start and never touched again; RoPE rotates Q and K inside **every layer's** attention. "Positional encoding is a vector added to the input" is only true of the older schemes.

</Note>
