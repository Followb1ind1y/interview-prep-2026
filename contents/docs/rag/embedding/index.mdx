## Level 0 · 从词到向量

### embedding 是什么，为什么能找近义表达？

Embedding 模型把一段文本映射为固定维度数值向量；训练目标让某些语义或检索相关的文本更接近。用户问“货还在路上能退吗”，政策写“运输中订单适用售后流程”，稠密检索可能相互匹配，即使没用同一措辞。

它不是事实数据库：向量相近不证明条款适用，也不保证精确识别 `P-17`、SKU 或日期。因此用元数据过滤与词法检索补足，最终回看原文。维度是向量长度，不等于知识量或答案质量。

## Level 0 · From text to vectors

### What is an embedding and why can it match paraphrases?

An embedding model maps text to a fixed-length vector so related queries and passages can be near each other. It may match “still in transit” with “shipping-stage after-sales process.” Similarity does not prove policy applicability or exact ID/date matching. The vector dimension is a representation size, not a quality guarantee.

1. Why is vector proximity not policy applicability?
2. Why do IDs need another signal?

## Level 1 · 相似度手算

### cosine、dot product 与归一化有什么区别？

示意二维向量：查询 `q=(1,0)`，候选 A=`(2,0)`，B=`(1,1)`。点积分别为 2 与 1；cosine 分别为 1 与约 0.707。点积受向量长度影响，cosine 只比方向；若先把所有向量单位化，点积才等于 cosine。L2 距离又是另一种排序依据。

真实 embedding 维度高得多，但计算逻辑相同。选模型和索引时核对官方推荐的相似度、是否自动归一化以及 query/document 编码方式；别把不同模型输出混进同一索引。

2. 更换 embedding 模型为何要重建索引？

## Level 1 · Similarity by hand

### How do cosine, dot product, and normalization differ?

For a toy query `(1,0)`, candidate A `(2,0)` has dot product 2 and cosine 1; B `(1,1)` has dot product 1 and cosine about 0.707. Dot product is affected by magnitude; cosine compares direction. Unit-normalized vectors make dot product equal cosine. Check the chosen model’s recommended metric and whether query and document encoders or prefixes differ.

## Level 2 · 编码与批处理

### query 与 document 要怎样编码和更新？

有些检索模型为 query 与 document 提供不同指令或前缀，有些使用相同调用。遵循该模型文档，离线统一编码文档，在线用对应 query 路径编码问题。记录模型 ID、版本、维度、归一化策略和文本预处理版本；改模型后建立新索引并做版本切换。

批量嵌入时处理空文本、超长截断、重试与幂等。被截掉的政策例外不会出现在向量里；存一条“embedding 成功”的日志无法证明完整性，要记录输入 token 数和截断状态。

## Level 2 · Encoding and indexing

### How should queries and documents be encoded and updated?

Some retrieval models require distinct query and document instructions; others do not. Follow the model contract. Version the model, dimensions, normalization, and preprocessing, and rebuild the index when changing them. Log truncation and empty inputs during batch embedding: a successful API response does not prove that the critical exception was encoded.

1. Why not invent query prefixes?
2. What reveals truncation of a long passage?

## Level 3 · 模型选择

### 多语言和领域 embedding 如何评估？

用真实中文、英文、混合编号、缩写与领域术语查询建小型 gold set；比较相同候选预算下的 Recall@K 与误召回，单独看稀有规则和跨语言匹配。再看延迟、吞吐、每次重建成本和数据驻留约束。大模型或高维向量未必胜出。

若 `P-17` 的准确条款仍找不到，先核对原始文本、chunk 边界和权限过滤；若只有同义改写差，再考虑 embedding。对照 [Sparse Retrieval](/docs/rag/sparse-retrieval) 与 [Hybrid Search](/docs/rag/hybrid-search)。

## Level 3 · Model selection

### How do you evaluate multilingual and domain embeddings?

Build a labeled set with Chinese, English, mixed IDs, abbreviations, and domain terms. Compare recall and false hits under the same candidate budget, then add latency, throughput, rebuild cost, and residency. A larger model or vector is not automatically better. Inspect parsing, chunking, and filters before blaming embeddings.
