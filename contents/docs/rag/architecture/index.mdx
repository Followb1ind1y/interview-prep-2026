## 三级回答

### Level 1 — 定义

RAG 把检索到的证据当作上下文，而不是只靠模型参数里的记忆。

### Level 2 — 机制

离线建索引；在线时：用户提问 → 检索 →（可选）重排 → 拼接 context → 生成。

### Level 3 — 工程

生产级 RAG 还要考虑数据入库质量、权限过滤、版本、评测和延迟预算。答错了先走 [Failure Diagnosis](/docs/rag/debugging)，不要一上来就换模型。

## Three-level answers

### Level 1 — Definition

RAG uses retrieved evidence as context instead of relying only on what's memorized in the model's parameters.

### Level 2 — Mechanism

Build the index offline. Online: the user asks → retrieve → (optionally) rerank → assemble context → generate.

### Level 3 — Engineering

Production RAG also has to deal with ingestion quality, permission filtering, versioning, evaluation, and a latency budget. When an answer is wrong, go through [Failure Diagnosis](/docs/rag/debugging) first — don't start by swapping models.
