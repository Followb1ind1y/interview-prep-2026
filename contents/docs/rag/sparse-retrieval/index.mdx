## Level 0 · 倒排索引

### 关键词检索如何快速找到含某词的文档？

倒排索引把词映射到出现它的文档或段 ID，而不是每次扫描全文。示意：`运输中 → {P-17#shipping, FAQ-2}`，`P-17 → {P-17#shipping}`。查询先用 postings 取候选，再做相关性排序。与向量检索相比，它很适合政策编号、SKU、错误码等准确字面量。

中文分词、大小写、连字符、同义词与数字格式会改变词项。`P-17` 被分成 `P` 和 `17` 时可能产生误匹配；对 ID 字段可设计 keyword/exact 匹配，正文再做正常分词。

## Level 0 · Inverted indexes

### How does lexical search find documents containing a term?

An inverted index maps each term to the passage IDs containing it. For example, `P-17` can point directly to its policy chunk. This is useful for exact IDs, SKUs, and error codes. Tokenization matters: splitting `P-17` into generic tokens can hurt precision, so keep an exact field for identifiers.

## Level 1 · BM25 直觉

### BM25 为什么更重视稀有词，又不会无限奖励重复词？

BM25 是基于词项匹配的排序函数：词越少见，区分力通常越强；同一词在段中出现多次会加分，但词频增益逐渐饱和；长文档会有长度归一化。示意 100 段里“退款”出现 70 次，`P-17` 只出现 2 次，命中 `P-17` 通常更能缩小范围。

这不是“精确字符串匹配就永远第一”：字段权重、分析器、停用词、长度和查询方式都影响分数。面试说清 TF 饱和、IDF、长度归一化即可；调参先看真实查询的错排样本。

## Level 1 · BM25 intuition

### Why does BM25 favor rare terms without unlimited repetition reward?

BM25 favors distinctive terms, saturates repeated term-frequency gains, and normalizes document length. If “refund” appears in 70 of 100 passages but `P-17` in only two, the identifier is more discriminative. Exact ranking still depends on field configuration and analyzers.

## Level 2 · 词法失效

### BM25 何时会漏掉意思相同的条款？

用户说“还在路上”，政策写“运输中”；如果分词和同义词配置没有桥接，词法匹配可能偏向无关 FAQ。稀疏检索也可能因 OCR 把 `P-17` 识别为 `P-I7` 而失效。因此用向量召回互补，但不能用 embedding 掩盖输入错误。

排错顺序：原文解析 → analyzer 实际 token → 字段/过滤 → BM25 候选与分数解释 → 同义词或混合检索。看查询是否真的进入了索引字段。

## Level 2 · Lexical failures

### When does BM25 miss a paraphrase?

Lexical retrieval may miss “still on the way” when the policy says “in transit.” OCR corruption can also break exact IDs. Dense retrieval complements this gap, but cannot repair missing or corrupted source text. Inspect extracted text, analyzer tokens, fields, filters, and lexical results in that order.

## Level 3 · 生产治理

### 词法索引如何与向量索引保持同一份真实资料？

两种索引应共享稳定 `doc_id/chunk_id/version`，同一发布批次生效。文档删改、ACL 收紧时同时撤销，读请求只看同一版本快照；否则 hybrid 会把已下线政策从 BM25 分支带回来。

给关键查询保留解释信息：命中词、字段、BM25 排名、过滤理由。调高 ID 字段权重前核对是否造成“提到 P-17 的旧 FAQ”压过现行 `P-17 v3`。

## Level 3 · Production governance

### How do lexical and vector indexes stay in sync?

Share stable IDs and publication versions across lexical and vector indexes. Apply deletion and ACL changes consistently, or hybrid retrieval can resurrect stale text from one branch. Inspect matched terms and fields before boosting an ID field; an old FAQ that merely mentions `P-17` may otherwise outrank the active policy.
