## 需要掌握

## 机制

```
exact kNN  →  O(N·d)  精确，但无法扩展
ANN        →  近似最近邻，用一点召回率换延迟
```

## 三级回答

### Level 1 — 定义

在高维向量里找最近邻。生产环境用近似算法，而不是全量扫描。

### Level 2 — 机制

HNSW 是图索引；IVF 先聚类，查询时只扫描部分桶；PQ 压缩向量来降内存。元数据过滤和向量检索的先后顺序会影响召回。

### Level 3 — 工程

N 到百万级以上，暴力搜索在延迟和 CPU/GPU 成本上都不划算。调 HNSW 的 ef / IVF 的 nprobe 是在召回率–延迟曲线上移动，不是开关。

## 面试问题

1. 为什么不能简单地暴力搜索所有 embedding？（Why can't you just brute-force search every embedding?）
2. HNSW 和 IVF 怎么选？（How do you choose between HNSW and IVF?）
3. PQ 对检索质量有什么影响？（How does PQ affect retrieval quality?）
4. 先过滤再检索，还是先检索再过滤？（Do you filter before retrieval or after?）

You must be able to answer: why can't you brute-force search every embedding?

## Must know

- ANN
- HNSW
- IVF
- PQ
- vector DB
- metadata filtering

## Mechanism

```
exact kNN  →  O(N·d)  exact, but doesn't scale
ANN        →  approximate nearest neighbors; trade a little recall for latency
```

## Three-level answers

### Level 1 — Definition

Finding nearest neighbors among high-dimensional vectors. Production systems use approximate algorithms, not a full scan.

### Level 2 — Mechanism

HNSW is a graph index; IVF clusters first and only scans some buckets per query; PQ compresses vectors to save memory. Whether metadata filtering runs before or after the vector search changes recall.

### Level 3 — Engineering

Past a million or so vectors, brute force doesn't pay off in latency or CPU/GPU cost. Tuning HNSW's ef or IVF's nprobe moves you along a recall–latency curve; it isn't an on/off switch.
