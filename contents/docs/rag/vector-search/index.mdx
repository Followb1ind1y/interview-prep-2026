## Level 0 · 最近邻基础

### 向量库到底在查什么？

给查询向量 `q`，最近邻搜索按指定距离或相似度返回若干文档向量及 ID。它不会验证答案正确、文档生效或用户有权访问。最简单的 Flat 索引比较所有向量，是**精确**基线；中小语料或硬件够用时完全可用。

先把 `P-17 v3`、`v2` 与 FAQ 编码，记录它们的向量 ID 到 chunk 元数据映射；查询后的第一步是检查返回 ID 与权限/版本，而不是直接交给模型。

## Level 0 · Nearest-neighbor basics

### What is the vector index searching for?

Nearest-neighbor search ranks indexed vectors by a chosen metric and returns IDs. It does not validate policy freshness or access rights. An exact Flat index scans all vectors and is a valid baseline, sometimes sufficient at small scale. Map every vector ID to its chunk and metadata.

## Level 1 · ANN 与 HNSW

### 什么时候需要近似搜索，HNSW 如何提速？

数据量或 P95 延迟让全量比较过贵时，用 ANN（approximate nearest neighbor）减少搜索范围，代价是可能漏掉真正最近的段。HNSW 建多层邻接图，从较稀疏层找方向，再在底层细找。`efSearch` 增大通常提高召回也增加查询工作量；建图参数也影响内存和构建时间。

用同一查询集把 HNSW Top-10 与 Flat Top-10 对比，测 ANN recall、P95 和内存。若政策关键段被 ANN 漏掉，调 `efSearch` 或考虑 Flat；不要把 ANN recall 与“答案正确率”混为一谈。

## Level 1 · ANN and HNSW

### When is approximate search useful and how does HNSW work?

ANN reduces comparisons when full scans miss latency or scale targets, at the cost of possible missed neighbors. HNSW traverses a layered proximity graph; increasing `efSearch` generally searches more broadly and costs more latency. Compare HNSW results with exact Flat results on the same vectors and filters, alongside P95 and memory.

## Level 2 · IVF 与 PQ

### IVF 和 PQ 分别压缩了什么工作？

IVF 先把空间分成若干簇，查询只探查 `nprobe` 个近邻簇；增大 `nprobe` 往往改善召回但变慢。PQ（product quantization）把向量分块并用码本压缩，降低内存与带宽，可能改变近邻排序；可对候选再用原始向量精排。HNSW、IVF、PQ 是可组合的设计点，不是一条必须依次经过的流水线。

若完整精确索引已满足 80 ms 的示意性预算，没有理由仅因“生产级”而加复杂 ANN。预算数字只是演示，实际用自身负载压测。

## Level 2 · IVF and PQ

### What work do IVF and PQ reduce?

IVF probes a subset of coarse clusters; `nprobe` trades speed for recall. PQ compresses vector representations into codes, saving memory and bandwidth but potentially changing rankings; exact vectors can refine candidates. These are alternative or composable design choices, not mandatory pipeline stages. Use workload measurements, not a blanket “production requires ANN” rule.

## Level 3 · 过滤与上线

### ACL 与元数据过滤会怎样影响 ANN？

企业检索必须在返回给用户前执行服务端授权。若先取全库 Top-10 再过滤，某租户可能只剩 1 条，甚至漏掉该租户本应排名第一的段；若先过滤，索引算法和过滤选择率又影响延迟。需要按引擎实际能力比较 pre-filter、post-filter、分区索引与补召回策略。

上线固定测试：无权文档永不出现在候选或日志外显；旧版被排除；高选择性过滤下与精确过滤基线比较召回。索引大小、更新成本、P95、授权准确性一起决策。

## Level 3 · Filtering and rollout

### How do ACL and metadata filters affect ANN?

Server-side authorization is mandatory. Fetching global Top-10 and filtering afterward can leave too few tenant results or miss a tenant’s true best match. Pre-filtering has different index and latency costs. Benchmark the engine’s real filter semantics against an exact filtered baseline, including access-denied negatives and stale-version exclusion.
