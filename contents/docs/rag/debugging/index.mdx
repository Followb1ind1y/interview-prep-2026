## 三级回答

### Level 1 — 定义

把「答错了」拆成检索 / 排序 / 上下文 / 生成四类故障。

### Level 2 — 机制

逐层看：检索回来的文档 id、它们的排名、实际拼进 prompt 的片段，以及模型有没有引用这些片段。对应指标：Recall@K 看检索，faithfulness 看生成。

### Level 3 — 工程

「你的 RAG 检索召回率 90%，但答案准确率只有 70%，怎么诊断？」检索本身是够的，问题出在排序、context 拼装，或者生成时没有忠于证据。

## 面试问题

1. RAG 答错了，你查什么？（RAG answer is wrong. What do you investigate?）
2. 正确的文档检索到了，答案却错了，为什么？（Correct document retrieved but answer wrong. Why?）
3. 没有答案的查询怎么处理？（How do you handle no-answer queries?）
4. 怎么降低 RAG 的延迟？（How would you reduce RAG latency?）
5. 怎么评测 RAG？（How do you evaluate RAG?）

This page matters a lot. When an interviewer says "your RAG answer is wrong," you should walk through this diagram without thinking.

## Must know

Debug layer by layer. Don't start by swapping the model.

## Mechanism

```
Question
 ↓
Was the correct document retrieved?
 ↓
NO → Retrieval problem
YES
 ↓
Was correct chunk ranked highly?
 ↓
NO → Ranking problem
YES
 ↓
Was context constructed correctly?
 ↓
NO → Context problem
YES
 ↓
Did LLM use the context?
 ↓
NO → Generation problem
```

## Three-level answers

### Level 1 — Definition

Breaking "the answer is wrong" into four kinds of failure: retrieval, ranking, context, and generation.

### Level 2 — Mechanism

Check each layer: the retrieved document ids, their ranks, the snippets that actually went into the prompt, and whether the model cited them. The matching metrics: Recall@K for retrieval, faithfulness for generation.

### Level 3 — Engineering

"Your RAG has 90% retrieval recall but only 70% answer accuracy. Diagnose it." Retrieval is good enough — the problem is in ranking, context assembly, or generation that doesn't stick to the evidence.

2. Correct document retrieved but answer wrong. Why?
3. How do you handle no-answer queries?
