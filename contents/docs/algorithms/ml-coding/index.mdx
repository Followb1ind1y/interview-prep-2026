## Level 0 · Classic structures

### 1. LRU cache (146)

Evict the least recently used item with O(1) `get` and `put`: a hash map for lookup plus an ordered structure for recency — `OrderedDict` has both.

</Locale>

```python
from collections import OrderedDict

class LRUCache:
    def __init__(self, capacity: int):
        self.cap = capacity
        self.data: OrderedDict[int, int] = OrderedDict()

    def get(self, key: int) -> int:
        if key not in self.data:
            return -1
        self.data.move_to_end(key)          # mark as most recently used
        return self.data[key]

    def put(self, key: int, value: int) -> None:
        if key in self.data:
            self.data.move_to_end(key)
        self.data[key] = value
        if len(self.data) > self.cap:
            self.data.popitem(last=False)   # evict least recently used (the front)
```

<Locale lang="zh">

**追问 1：不许用 OrderedDict。** 用“哈希表 + 双向链表”：哈希表存 `key → 节点`，链表头部是最近使用、尾部是最久未使用；用两个哨兵节点（head、tail）避免空链表特判。移动节点 = 从原位置摘下 + 插到头部，都是 O(1)。

**追问 2：多线程安全吗？** 不安全。最简单是每个方法外加一把锁；高并发时可以分段加锁（按 key 哈希分成多个 LRU）。

**追问 3：和 AI 系统的联系？** 应用层答案缓存、embedding 缓存、[Caching](/docs/context/caching) 里的检索结果缓存都需要淘汰策略；推理引擎的前缀缓存（如 vLLM 的块缓存）也用类似 LRU 的策略淘汰 KV 块。

Follow-ups: without `OrderedDict`, use a hash map to doubly linked list nodes with head/tail sentinels — unlink and push to front in O(1); thread safety needs a lock or sharded LRUs; AI links include answer and embedding caches and KV-block eviction in prefix caches.

### 2. Token-bucket rate limiter

Implement `allow()` with capacity and refill rate (see [API Engineering](/docs/production/api-engineering) Level 3).

</Locale>

```python
import threading
import time

class TokenBucket:
    def __init__(self, rate: float, capacity: float):
        self.rate, self.capacity = rate, capacity
        self.tokens = capacity
        self.last = time.monotonic()          # monotonic: immune to wall-clock jumps
        self.lock = threading.Lock()

    def allow(self, cost: float = 1.0) -> bool:
        with self.lock:
            now = time.monotonic()
            # lazy refill: no background thread, just compute elapsed time
            self.tokens = min(self.capacity, self.tokens + (now - self.last) * self.rate)
            self.last = now
            if self.tokens >= cost:
                self.tokens -= cost
                return True
            return False
```

<Locale lang="zh">

关键点：

- **懒补充**：不需要后台线程定时加令牌，每次调用时按经过的时间计算。
- 用 `time.monotonic()` 而不是 `time.time()`——系统时间被调整时不会出错。
- `cost` 参数：LLM 场景按 **token 数**扣，而不只是按请求数。

**追问：多台机器怎么共享限流？** 状态放 Redis，用 Lua 脚本把“读取 → 计算 → 写回”做成原子操作；或给每个实例分配一部分配额（见 [Scaling](/docs/production/scaling) Level 2）。

**追问：和滑动窗口计数有什么区别？** 令牌桶允许突发（最多到容量），滑动窗口按时间窗口严格计数。

### 3. Retry decorator with exponential backoff and jitter

Retry only retryable errors with full jitter (see [API Engineering](/docs/production/api-engineering) Level 2).

</Locale>

```python
import asyncio
import functools
import random

def retry(max_attempts: int = 4, base: float = 0.5, cap: float = 8.0,
          retry_on: tuple[type[Exception], ...] = (TimeoutError, ConnectionError)):
    def decorator(fn):
        @functools.wraps(fn)                  # keep the wrapped function's name and docstring
        async def wrapper(*args, **kwargs):
            for attempt in range(max_attempts):
                try:
                    return await fn(*args, **kwargs)
                except retry_on:
                    if attempt == max_attempts - 1:
                        raise                 # out of attempts: surface the error
                    await asyncio.sleep(random.uniform(0, min(cap, base * 2 ** attempt)))
        return wrapper
    return decorator

@retry(max_attempts=3)
async def call_model(prompt: str) -> str:
    ...
```

<Locale lang="zh">

追问点：

- 为什么要 `functools.wraps`？——保留原函数名和文档，日志和调试才看得懂。
- 为什么只捕获 `retry_on`？——400、401 之类重试也不会成功（见 API Engineering 的错误分类）。
- 怎么支持服务端的 `Retry-After`？——自定义异常携带等待时间，有就用它。
- 怎么加总 deadline？——记录开始时间，剩余时间不够就不再等待。
- **有副作用的调用能这样重试吗？** 不能，要配合幂等键（见 API Engineering Level 4）。

Follow-ups: `functools.wraps` preserves names for logs; only retryable errors (4xx never succeed); honor `Retry-After` via custom exceptions; add an overall deadline; never retry side effects without idempotency keys.

### 4. Concurrency-limited async batch

Call a model for 1,000 prompts with at most 10 in flight, 30 s timeouts, and isolated failures.

</Locale>

```python
import asyncio

async def run_batch(prompts: list[str], call, max_concurrency: int = 10,
                    timeout: float = 30.0) -> list[str | Exception]:
    sem = asyncio.Semaphore(max_concurrency)

    async def one(prompt: str) -> str | Exception:
        async with sem:                                   # at most N concurrent calls
            try:
                return await asyncio.wait_for(call(prompt), timeout)
            except Exception as e:                        # isolate failures per item
                return e

    return await asyncio.gather(*(one(p) for p in prompts))   # results keep input order
```

<Locale lang="zh">

追问点：

- 为什么不直接 `gather` 1,000 个？——会同时发出 1,000 个请求，触发供应商 429、耗尽连接池。
- `gather` 的返回顺序？——和输入顺序一致。
- 为什么在 `one` 里捕获异常？——否则一个失败会让 `gather` 抛出，其他结果丢失（也可以用 `return_exceptions=True`）。
- 怎么按 TPM 而不只是并发数限流？——在 `async with sem` 里再加一个异步版的令牌桶。
- 这些请求不着急的话？——用供应商的 Batch API，价格约五折（见 [Cost](/docs/production/cost) Level 3）。

### 5. Incremental SSE parsing

Chunks can split events; feed text and return only complete events.

</Locale>

```python
class SSEParser:
    def __init__(self):
        self.buffer = ""

    def feed(self, chunk: str) -> list[dict]:
        self.buffer += chunk
        events = []
        while "\n\n" in self.buffer:                       # a blank line ends an event
            raw, self.buffer = self.buffer.split("\n\n", 1)
            event, data = "message", []
            for line in raw.split("\n"):
                if not line or line.startswith(":"):       # comment / heartbeat
                    continue
                field, _, value = line.partition(":")
                value = value[1:] if value.startswith(" ") else value
                if field == "event":
                    event = value
                elif field == "data":
                    data.append(value)
            if data:
                events.append({"event": event, "data": "\n".join(data)})
        return events

p = SSEParser()
p.feed('event: delta\ndata: {"text": "你的')     # -> []  (incomplete)
p.feed('订单"}\n\n')                              # -> [{"event": "delta", "data": '{"text": "你的订单"}'}]
```

追问点：

- 为什么要缓冲？——一个事件、甚至一个 UTF-8 多字节字符都可能被切开（字节流还需要增量解码器 `codecs.getincrementaldecoder`）。
- 以冒号开头的行是什么？——注释，常用作心跳保持连接（见 API Engineering Level 1）。
- 一个事件多行 `data` 怎么处理？——按规范用换行拼接。
- 收到 `data` 是 JSON 片段（如工具调用参数）时？——要累积到完整再解析，不能边收边执行。

## Level 2 · numpy numerics

### 6. Numerically stable softmax

</Locale>

```python
import numpy as np

def softmax(x: np.ndarray, axis: int = -1) -> np.ndarray:
    x = x - x.max(axis=axis, keepdims=True)   # subtract max: exp never overflows
    e = np.exp(x)
    return e / e.sum(axis=axis, keepdims=True)

softmax(np.array([1000.0, 1001.0]))           # works; naive exp(1000) would be inf
```

<Locale lang="zh">

为什么减最大值：`exp(1000)` 溢出成无穷大，结果变成 `nan`。减去最大值后所有指数 ≤ 0，最大项是 `exp(0) = 1`；而 softmax 的结果不变（分子分母同乘 `exp(-max)`）。追问：`keepdims=True` 是为了广播；log-softmax 用 log-sum-exp 技巧。

### 7. 缩放点积注意力（含因果掩码）

`Attention(Q, K, V) = softmax(Q Kᵀ / √d) V`（机制见 [Transformer](/docs/llm/transformer)）。

</Locale>

<Locale lang="en">

`exp(1000)` overflows to inf and yields nan; subtracting the max keeps exponents ≤ 0 without changing the result. `keepdims` enables broadcasting; log-softmax uses log-sum-exp.

### 7. Scaled dot-product attention with a causal mask

`softmax(QKᵀ/√d)V` — see [Transformer](/docs/llm/transformer).

</Locale>

```python
def attention(Q: np.ndarray, K: np.ndarray, V: np.ndarray, causal: bool = False) -> np.ndarray:
    """Q: (..., n_q, d), K: (..., n_k, d), V: (..., n_k, d_v)"""
    d = Q.shape[-1]
    scores = Q @ K.swapaxes(-1, -2) / np.sqrt(d)            # (..., n_q, n_k)
    if causal:
        n_q, n_k = scores.shape[-2:]
        future = np.triu(np.ones((n_q, n_k), dtype=bool), k=1)
        scores = np.where(future, -np.inf, scores)          # position i can't see j > i
    return softmax(scores, axis=-1) @ V                     # (..., n_q, d_v)

rng = np.random.default_rng(0)
x = rng.standard_normal((4, 8))                              # 4 tokens, dim 8
out = attention(x, x, x, causal=True)                        # (4, 8)
```

<Locale lang="zh">

追问点：

- 为什么除以 √d？——点积的方差随维度增大，不缩放 softmax 会过于尖锐、梯度变小。
- 掩码为什么用 `-inf`？——`exp(-inf) = 0`，被遮住的位置权重恰好为 0。
- 复杂度？——O(n² · d) 时间、O(n²) 空间存分数矩阵；FlashAttention 通过分块计算避免存整个矩阵（见 [Inference](/docs/llm/inference) Level 6）。
- 多头怎么做？——把 d 拆成 h 个头，reshape 成 `(h, n, d/h)` 后上面的函数可直接批量计算（因为支持前导维度 `...`）。

### 8. 余弦相似度 Top-K 检索

</Locale>

<Locale lang="en">

Follow-ups: √d keeps logits from growing with dimension (sharp softmax, small gradients); `-inf` gives exactly zero weight; O(n²·d) time and O(n²) memory for scores — FlashAttention tiles to avoid materializing them; multi-head reshapes to `(h, n, d/h)` and reuses the batched function.

### 8. Cosine Top-K retrieval

Return the k documents most similar to a query (see [Embedding](/docs/rag/embedding) Level 0).

</Locale>

```python
def top_k_cosine(query: np.ndarray, docs: np.ndarray, k: int) -> tuple[np.ndarray, np.ndarray]:
    q = query / np.linalg.norm(query)
    D = docs / np.linalg.norm(docs, axis=1, keepdims=True)
    sims = D @ q                                    # (N,) cosine = dot of unit vectors
    k = min(k, len(sims))
    idx = np.argpartition(-sims, k - 1)[:k]         # unordered top-k in O(N)
    idx = idx[np.argsort(-sims[idx])]               # sort only those k
    return idx, sims[idx]
```

<Locale lang="zh">

追问点：

- 为什么用 `argpartition`？——全排序 O(N log N)，`argpartition` 找前 k 个是 O(N)，再对 k 个排序 O(k log k)。
- 文档向量可以预先归一化吗？——可以，存储时就归一化，查询时只需一次矩阵乘法。
- 零向量怎么办？——除以 0 会得到 `nan`，要加一个很小的 epsilon 或过滤。
- 1,000 万个文档还这么做吗？——不，暴力是 O(N·d)，要用 ANN 索引（见 [Vector Search](/docs/rag/vector-search)）。

Follow-ups: `argpartition` is O(N) plus O(k log k) versus O(N log N); pre-normalize stored vectors; guard zero vectors with epsilon; at 10M documents use ANN ([Vector Search](/docs/rag/vector-search)).

### 9. BPE training

Repeatedly count adjacent symbol pairs and merge the most frequent (see the BPE walkthrough in [Tokenization](/docs/llm/tokenization)).

</Locale>

```python
from collections import Counter

def train_bpe(word_freqs: dict[str, int], num_merges: int) -> list[tuple[str, str]]:
    vocab = {tuple(word): freq for word, freq in word_freqs.items()}   # start from characters
    merges = []
    for _ in range(num_merges):
        pairs = Counter()
        for symbols, freq in vocab.items():
            for a, b in zip(symbols, symbols[1:]):
                pairs[(a, b)] += freq
        if not pairs:
            break
        best = max(pairs, key=pairs.get)              # most frequent adjacent pair
        merges.append(best)
        new_vocab = {}
        for symbols, freq in vocab.items():
            out, i = [], 0
            while i < len(symbols):
                if i + 1 < len(symbols) and (symbols[i], symbols[i + 1]) == best:
                    out.append(symbols[i] + symbols[i + 1])
                    i += 2
                else:
                    out.append(symbols[i])
                    i += 1
            new_vocab[tuple(out)] = new_vocab.get(tuple(out), 0) + freq
        vocab = new_vocab
    return merges

train_bpe({"low": 5, "lower": 2, "newest": 6, "widest": 3}, 3)
# first merges: ('e', 's'), ('es', 't'), ...
```

<Locale lang="zh">

追问点：

- 复杂度？——每轮重新统计所有对 O(总符号数)；生产实现只增量更新受影响的对，并用优先队列。
- 频率相同时怎么选？——需要确定的平局规则，否则不同运行结果不同。
- 编码新词时怎么用合并规则？——按学到的顺序依次应用合并。
- byte-level BPE 的区别？——从 256 个字节开始，而不是字符，所以永远不会有未登录词。
- 词边界？——真实实现会在词尾加标记或按空格预切分，避免跨词合并。
