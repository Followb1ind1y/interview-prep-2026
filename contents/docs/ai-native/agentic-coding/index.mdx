## 三级回答

### Level 1 — 定义

把写代码看成一个有环境反馈的循环，而不是一次性生成。

### Level 2 — 机制

测试、类型检查、linter、复现脚本都是「观察」。没有观察，模型只能「觉得自己写对了」。

### Level 3 — 工程

评测看的是任务有没有完成、用了几步，而不是第一版代码漂不漂亮。测试要在沙箱里跑。

## Three-level answers

### Level 1 — Definition

Treating coding as a loop with feedback from the environment, not a single generation.

### Level 2 — Mechanism

Tests, type checks, linters, and repro scripts are all observations. Without them, the model can only "feel" that the code is right.

### Level 3 — Engineering

Evaluation looks at whether the task got done and how many steps it took — not whether the first draft looks nice. Run the tests inside the sandbox.

## Interview questions

1. How does an agent know its code is correct?
2. How do you verify changes in a repo with no tests?
3. How do you keep an agent from touching unrelated files?
4. How do you verify agent-generated code?
