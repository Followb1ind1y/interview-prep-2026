<Locale lang="zh">

## 三级回答

### Level 1 — 定义

按请求的特征，把流量分到不同的模型。

### Level 2 — 机制

可以用规则（长度、任务类型），或者先用小分类器 / 小模型判断难度。Cascade：先用便宜模型，置信度低再升级到强模型。

### Level 3 — 工程

路由错了，简单问题会花冤枉钱，难题会答崩。必须有 fallback 和 A/B 测试。这和 agent 选工具不同：这里选的是「用哪个大脑」，不是「用哪个工具」。

## 面试问题

## Three-level answers

### Level 1 — Definition

Sending traffic to different models based on what each request looks like.

### Level 2 — Mechanism

Use rules (length, task type), or have a small classifier or small model judge difficulty first. A cascade starts with the cheap model and escalates to the strong one when confidence is low.

### Level 3 — Engineering

Misrouting makes easy questions expensive and breaks hard ones. You need fallbacks and A/B tests. This is different from an agent choosing tools: here you're choosing which brain, not which tool.

## Interview questions

1. What signals do you use to judge how hard a query is?
2. Compared with always calling the large model, where does a cascade save money and where does it add latency?
3. What triggers a fallback?
4. How do you use A/B testing to prove routing didn't hurt quality?
