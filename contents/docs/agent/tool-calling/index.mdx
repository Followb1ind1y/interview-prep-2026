## 三级回答

### Level 1 — 定义

模型输出结构化的工具名和参数，由运行时去执行，再把结果喂回给模型。

### Level 2 — 机制

Schema 限制了能调用的范围。校验挡住模型幻觉出来的参数。超时和重试要考虑幂等，避免重复下单、重复写入。

### Level 3 — 工程

工具失败不是「再问一次模型」就完事。要分类处理：参数错误、下游 5xx、权限问题、超时。工具太多会降低选择准确率，这部分转到 Context Construction。

## Three-level answers

### Level 1 — Definition

The model outputs a structured tool name and arguments, the runtime executes the call, and the result gets fed back to the model.

### Level 2 — Mechanism

The schema limits what can be called. Validation blocks hallucinated arguments. Timeouts and retries have to respect idempotency so you don't place an order twice or write the same record twice.

### Level 3 — Engineering

A tool failure isn't fixed by "just ask the model again." Classify it: bad arguments, downstream 5xx, permissions, timeout. Too many tools lower selection accuracy — that's a Context Construction problem.
