<Locale lang="zh">

Agent 不是“更长的 prompt”，也不是某个框架的名字。它是一个由 **harness（运行与编排层）** 驱动的系统：模型查看当前状态、选择下一步；harness 安全地执行允许的工具调用，把真实结果放回状态；直到任务完成或被安全地停止。

这一页先不讲复杂的 Planning、Memory 或 Multi-Agent。先把最小闭环讲清楚：**模型不会自己调用 API，也不会天然知道工具做完后的世界发生了什么。** 这两个空白正是 agent loop 要填上的部分。

## 这一页怎么学

An agent is neither a longer prompt nor the name of a framework. It is a system driven by a **harness**, or runtime/orchestration layer: the model sees the current state and chooses a next step; the harness safely executes permitted tools and returns real results to that state; the system continues until the task finishes or stops safely.

This page deliberately postpones complex planning, memory, and multi-agent designs. First build the minimal closed loop: **a model does not execute an API call by itself, and it does not automatically know what changed after a tool ran.** The agent loop fills those two gaps.

## How to work through this page

One procurement-negotiation assistant runs through the whole page. A user says: “Check Acme's latest quote. If unit price is at most 10.20 and payment is Net 30, prepare the next counteroffer; otherwise explain the blocker.” The assistant may read quotes and policy and create a draft; it may not send a commitment itself.

## Level 0 · 最小积木：谁在做决定，谁在改变世界？

### 一次 LLM 调用为什么还不是 Agent？

一次调用是：把 prompt 交给模型，模型生成一段文字或一个结构化的工具调用请求，然后这一次推理结束。它很适合总结、分类、改写等“输入已经足够、答案可以直接生成”的任务。

Agent 在这之外加上了 **状态、可执行动作和反馈回路**。目标不变，但它可以根据刚刚查到的真实信息决定下一步。因此，最小 Agent 不是“会思考的模型”，而是“模型在受控环境中多次作出下一步决策”的系统。

以贯穿例子为例，直接问模型“Acme 能不能接受？”有一个根本问题：模型并没有看到最新报价，也不能替你读取采购系统。它最多生成一个看起来合理的猜测。Agent 则可以先请求读取报价，再根据结果决定是否读取政策、创建草稿或停止。

<Note title="先选对复杂度" type="tip">

如果报价、规则和下一步已经完全确定，例如“每晚把所有过期报价标记为过期”，这是 workflow，不需要让模型在每一步自由选择。只有下一步取决于未知信息、文本语义或工具结果时，loop 才带来价值。[Workflow vs Agent](/docs/agent/workflow-vs-agent) 会专门比较这个判断。

</Note>

### 模型、harness、tool、environment 分别是什么？

- **Model（模型）**：根据当前 context 生成自然语言、结构化结果，或“我要调用哪个工具、参数是什么”的请求。它提出动作，不应被当成执行者或事实来源。
- **Harness（运行与编排层）**：应用代码。它保存状态、组装下一轮 context、检查权限和参数、调用工具、记录 trace，并决定何时强制停止。
- **Tool（工具）**：一份受约束的能力，例如 `get_latest_quote`、查数据库、搜索文档或创建草稿。工具返回的是 observation（观察结果）。
- **Environment（环境）**：工具接触到的真实世界及其状态，例如采购数据库、文件、网页和可写入的草稿系统。

一个简单记法是：**模型提议，harness 把关并编排，工具执行，环境给出真相与副作用。** 模型输出里写了“已创建草稿”不等于草稿真的存在；只有工具的成功结果才能证明环境已改变。

<Note title="Reason 不等于公开原始思维链" type="warning">

在图里把中间步骤写成 Reason / Decide，意思是“模型基于当前状态选择下一步”。工程上应依赖可观察的决策、工具调用、结果和验收条件来调试，而不是要求或存储模型的原始内部推理文本。

</Note>

## Level 0 · Minimum building blocks: who decides and who changes the world?

### Why is one LLM call not an agent yet?

One call sends a prompt to a model; the model generates text or a structured request to call a tool; then that inference ends. It is a great fit for summarization, classification, and rewriting, where the input is already sufficient and an answer can be generated directly.

An agent adds **state, executable actions, and a feedback loop**. The goal stays the same, but the system can choose its next step from newly retrieved facts. So a minimal agent is not “a model that thinks”; it is a system in which a model makes multiple next-step decisions in a controlled environment.

In the running example, asking a model directly “Will Acme accept?” has a fundamental flaw: the model has not seen the latest quote and cannot read the procurement system for you. It can only make a plausible guess. An agent can request the quote first, then decide whether to check policy, create a draft, or stop.

<Note title="Choose the right amount of complexity" type="tip">

If the quote, rules, and next step are fully specified — for example, “mark all expired quotes every night” — use a workflow. There is no reason to let a model freely choose each step. A loop earns its cost only when the next step depends on unknown information, language semantics, or tool outcomes. [Workflow vs Agent](/docs/agent/workflow-vs-agent) compares this choice in depth.

</Note>

### What are the model, harness, tool, and environment?

- **Model**: produces natural language, structured output, or a request naming a tool and arguments from the current context. It proposes an action; it is neither the executor nor the source of truth.
- **Harness**: application code that stores state, assembles the next context, checks authorization and arguments, invokes tools, records a trace, and enforces stopping rules.
- **Tool**: a constrained capability, such as `get_latest_quote`, a database query, document search, or draft creation. Its result becomes an observation.
- **Environment**: the real systems and state reached by the tools: a procurement database, files, websites, or a writable draft system.

An easy rule is: **the model proposes; the harness governs and orchestrates; tools execute; the environment supplies truth and side effects.** A model message saying “I created the draft” does not prove a draft exists. Only a successful tool result proves that the environment changed.

<Note title="Reason does not mean exposing raw chain of thought" type="warning">

Reason / Decide in a diagram means “the model selects a next step from current state.” In production, debug with observable decisions, tool calls, results, and acceptance criteria — not by requiring or storing raw internal reasoning text.

</Note>

## Level 1 · 状态如何走一圈：Observe → Decide → Act

### Observe 到底在“观察”什么？

Observe 不是一定要看屏幕。它是 harness 为下一次模型推理准备的**当前可用状态**：用户目标、对话与工具结果、允许使用的工具、持久化业务状态，以及预算与权限等约束。

采购例子刚开始时，harness 可以组装出下面的快照。这里 `draft` 为 `false` 不是模型猜出来的，而是应用从环境读到的状态。

```json
{
  "goal": "核对 Acme 报价；满足价格和付款条件才准备反报价",
  "deal_state": { "vendor": "Acme", "latest_quote": "unknown", "draft": false },
  "allowed_tools": ["get_latest_quote", "get_negotiation_policy", "create_counteroffer_draft"],
  "constraints": ["不能发送承诺", "最多 5 次工具调用"]
}
```

Observe 的关键不是“把所有历史原样塞回 prompt”。每一轮只选择下一个决定真正需要的事实：错误信息、工具结果、批准状态、文件摘要等。历史无限增长会挤占 context window，并让模型更难找出当前事实；如何挑选、压缩和隔离这些内容，是后面的 Context Engineering 问题。

### Decide 与 Act 怎样把新事实带回模型？

第一轮模型看到 `latest_quote: unknown`，合理的决策是请求：

```text
get_latest_quote(vendor="Acme")
```

这只是**请求**。harness 要验证参数和权限，真正执行工具；工具回来的 observation 才是：

```text
unit_price = 10.15
payment_terms = "Net 45"
quote_id = "Q-817"
```

harness 把结果追加进状态，开启下一轮 Observe。现在模型有了一个新事实：价格达标，但付款条款不达标。因此它不应该创建反报价，而应请求读取政策，弄清 `Net 45` 是否可接受、能否用别的条款交换。这就是 loop 的价值：**上一轮 Action 改变了下一轮模型能依据什么作决定。**

第二轮若政策结果说“只有 Net 30 才能创建此类草稿”，模型就会选择一个终止性的用户回复，例如“价格满足，但 Net 45 不符合政策；需要你批准例外或与供应商谈付款条款。”它不会为了凑满五步继续调用工具。

## Level 1 · One trip around the loop: Observe → Decide → Act

### What does Observe actually observe?

Observe does not necessarily mean looking at a screen. It is the **current usable state** that the harness prepares for the next model inference: the user goal, conversation and tool results, allowed tools, persistent business state, and constraints such as budget and permissions.

At the start of the procurement example, the harness can assemble this snapshot. `draft: false` is not something the model guessed; it is state the application read from the environment.

```json
{
  "goal": "Check Acme's quote; create a counteroffer draft only if price and payment conditions pass",
  "deal_state": { "vendor": "Acme", "latest_quote": "unknown", "draft": false },
  "allowed_tools": ["get_latest_quote", "get_negotiation_policy", "create_counteroffer_draft"],
  "constraints": ["Do not send commitments", "At most 5 tool calls"]
}
```

Observe does not mean dumping every past message into the prompt unchanged. Each round selects the facts needed for the next decision: errors, tool results, approval state, and file summaries. Unlimited history consumes the context window and makes current facts harder to find. Selecting, compressing, and isolating it is the later Context Engineering problem.

### How do Decide and Act return a new fact to the model?

On the first round, the model sees `latest_quote: unknown`, so a sensible decision is:

```text
get_latest_quote(vendor="Acme")
```

That is only a **request**. The harness validates its arguments and authority and actually runs the tool. The resulting observation is:

```text
unit_price = 10.15
payment_terms = "Net 45"
quote_id = "Q-817"
```

The harness appends that result to state and begins the next Observe. The model now has a new fact: price passes, but payment terms do not. It should not create a counteroffer yet; it should request the policy to find out whether `Net 45` is acceptable or tradeable. This is the value of the loop: **an Action changes what the next model decision can be based on.**

If the second tool result says that only Net 30 permits this draft, the model chooses a terminal user reply: “The price passes, but Net 45 fails policy; I need your approval for an exception or a negotiation on payment terms.” It does not keep calling tools merely to use all five steps.

</Locale>

```text
user goal + durable state + constraints
                 │
                 ▼
          Observe: build context
                 │
                 ▼
         Decide: model returns
          final answer OR tool request
                 │                 │
                 │                 ▼
                 │        Act: harness validates
                 │        and executes the tool
                 │                 │
                 ▼                 ▼
            return to user   observation → state → Observe
```

### 最小 loop 的伪代码是什么样？

下面故意省略了并发、多工具调用和流式输出，只保留责任边界。最容易犯的错误是把 `execute` 写成“相信模型已经做完了”，或者执行完却忘记把结果放回下一轮 context。

```python
state = initial_state(user_request)

for step in range(MAX_STEPS):
    response = model(context=build_context(state), tools=allowed_tools(state))
    if response.is_final:
        return response.message

    call = validate_tool_request(response.tool_call, state)
    result = execute(call)                 # harness / tool touches the environment
    state = add_observation(state, call, result)

return safe_stop("step limit reached", state)
```

真实系统还要处理工具超时、重复调用、写操作确认和可恢复 trace；它们放在 [Reliability](/docs/agent/reliability) 和 [Security](/docs/agent/security)。但即使只有两个工具，`result → state → next context` 也不能省掉，否则它不是闭环。

### What does minimal loop pseudocode look like?

This intentionally omits concurrency, multiple tool calls, and streaming. It keeps only the responsibility boundary. A common mistake is writing `execute` as though the model already performed the action, or executing the tool but failing to return its result in the next context.

```python
state = initial_state(user_request)

for step in range(MAX_STEPS):
    response = model(context=build_context(state), tools=allowed_tools(state))
    if response.is_final:
        return response.message

    call = validate_tool_request(response.tool_call, state)
    result = execute(call)                 # harness / tool touches the environment
    state = add_observation(state, call, result)

return safe_stop("step limit reached", state)
```

Production systems also need to handle tool timeouts, repeat calls, confirmation for writes, and recoverable traces. Those belong in [Reliability](/docs/agent/reliability) and [Security](/docs/agent/security). But even with two tools, `result → state → next context` is indispensable; without it, the system is not closed-loop.

## Level 2 · 让 loop 正确结束：完成、进展与安全停止

### 什么情况应当停止，而不是再来一轮？

Loop 的目的不是“尽可能多地调用工具”，而是用有限步骤达到一个验收条件（acceptance condition）。在例子中，验收条件不是“调用了报价工具”，而是以下之一：

- 已基于最新报价和政策创建了**可审核的草稿**；
- 发现明确的业务卡点，并向用户说明缺少什么批准或信息；
- 用户拒绝继续，或涉及不可自动执行的高风险动作；
- 系统到达步骤、时间、token 或成本预算，不能再安全推进。

正常完成应由明确的结果表示，例如结构化的 `final`、创建草稿工具的成功 observation，或等待人工批准的状态。不要只用“模型这次没调用工具”当作唯一成功信号：它可能真的完成了，也可能是不知道下一步、上下文被挤掉，或者工具定义写得不清楚。

<Note title="外部副作用要分级" type="danger">

“模型要求调用写工具”不等于“马上执行写操作”。发送谈判承诺、修改订单、付款、删除数据等动作，harness 应在执行前做授权、业务规则校验、幂等检查；必要时把 loop 停在“等待用户批准”。模型的概率性决策不能绕过系统权限。

</Note>

### 怎样判断它在推进，还是在空转？

每一轮都记录至少四件事：本轮目标、工具名与规范化参数、结果摘要、以及为什么这一步让任务离验收条件更近。观察下面的对比：

```text
有进展：read_quote(Acme) → 得到 Q-817 / Net 45
        read_policy(Net 45) → 得到 “必须 Net 30”
        final → 明确卡点并请求批准

空转：  read_quote(Acme) → 超时
        read_quote(Acme) → 同样超时
        read_quote(Acme) → 同样超时
```

第二段不是“模型更努力了”，而是没有新增事实。harness 可以检测连续相同的工具和参数、重复的错误指纹、状态摘要不变、或剩余预算不足；达到阈值就停止、换确定性 fallback，或交给人。这样 trace 才能回答“为什么花了钱却没完成”，也才能把问题分到模型决策、工具可靠性、权限还是缺失状态。

量感（教学）：同一 Acme 任务若本可 2 次工具调用 + 1 次 final 结束（约 3 轮模型推理），空转重试 8 次会把 token / 延迟近似放大 3–4 倍，且仍无新事实。预算不是“省钱洁癖”，而是失败模式的硬边界。

### 为什么最大步数、时间和预算都需要？

- **最大步数**限制错误重试和没有终点的规划；
- **超时**限制一次工具或整次任务占用用户等待时间；
- **token / 成本预算**限制长 observation、长上下文和昂贵模型调用；
- **权限与批准边界**限制即使“看似成功”也不应发生的副作用。

这些是兜底，不是任务成功的定义。好的 loop 会在碰到硬上限前，基于验收条件主动结束；硬上限负责把异常路径变成诚实、可恢复的失败，而不是静默地继续烧钱。

## Level 2 · Ending a loop correctly: completion, progress, and safe stopping

### When should a loop stop rather than take another turn?

The goal of a loop is not “call as many tools as possible.” It is to reach an acceptance condition in bounded steps. In the running example, the condition is not “the quote tool was called.” It is one of these:

- a **reviewable draft** was created from the latest quote and policy;
- a concrete business blocker was found and the user was told which approval or information is missing;
- the user declines to continue, or the next action is too high-risk to automate;
- the system reaches its step, time, token, or cost budget and can no longer progress safely.

Normal completion should have an explicit result: a structured `final`, a successful draft-creation observation, or a state awaiting human approval. Do not treat “the model made no tool call this time” as the only success signal. It may have finished, but it may also be stuck, have lost context, or have unclear tool definitions.

<Note title="Classify external side effects" type="danger">

“The model requested a write tool” does not mean “execute the write immediately.” Before a negotiation commitment, order change, payment, or deletion, the harness should check authorization, business rules, and idempotency; when necessary, it stops at “awaiting user approval.” A probabilistic model decision must not bypass system permissions.

</Note>

### How do you tell progress from spinning?

For every round, record at least four items: its goal, tool name plus normalized arguments, summarized result, and why that step moved the task closer to acceptance. Compare these traces:

```text
Progress: read_quote(Acme) → Q-817 / Net 45
          read_policy(Net 45) → “Net 30 required”
          final → states the blocker and requests approval

Spinning:  read_quote(Acme) → timeout
           read_quote(Acme) → same timeout
           read_quote(Acme) → same timeout
```

The second trace is not the model trying harder; it has acquired no new fact. A harness can detect identical consecutive tools and arguments, repeated error fingerprints, an unchanged state summary, or insufficient remaining budget. At a threshold, it stops, switches to a deterministic fallback, or hands off to a person. A useful trace then localizes the cause to model choice, tool reliability, authorization, or missing state.

Teaching-scale numbers: the same Acme task may finish in two tool calls plus one final (about three model turns). Eight spinning retries roughly multiply tokens and latency by 3–4× with no new fact. Budgets are hard boundaries on failure modes, not thriftiness for its own sake.

### Why do maximum steps, time, and budget all matter?

- **maximum steps** bound bad retries and plans with no end;
- **timeouts** bound how long one tool or the entire task occupies the user;
- **token / cost budgets** bound long observations, growing context, and expensive model calls;
- **authorization and approval boundaries** bound side effects that should not happen even if they look successful.

These are fallbacks, not the definition of success. A good loop ends proactively on its acceptance condition before hitting a hard limit. The hard limit turns an exceptional path into an honest, recoverable failure instead of silently spending more money.

## 陷阱

<Note title="把工具定义交给模型，不等于给了系统能力" type="warning">

工具 schema 只让模型知道“可以请求什么”。没有 executor、鉴权、参数校验、错误处理和结果回传时，它只是文本描述，不是可靠的行动能力。

</Note>

<Note title="Observe 不是原样塞满聊天记录" type="warning">

上一轮所有 tool output 都放进 context，短期可能有效，长任务会越来越慢、越来越贵，也更容易抓不住当前事实。状态要按下一步决策来筛选和总结。

</Note>

<Note title="能循环不代表能自我纠错" type="warning">

Loop 只提供“看到结果后再次决策”的机会。工具返回错数据、验收条件写错、模型误读 observation，都会让它持续而自信地做错。必须用 trace 和针对性评测验证。

</Note>

## Traps

<Note title="Giving a tool definition to a model is not giving the system a capability" type="warning">

A tool schema tells a model only what it may request. Without an executor, authorization, argument validation, error handling, and result return, it is a text description — not reliable agency.

</Note>

<Note title="Observe is not a raw dump of chat history" type="warning">

Putting every prior tool output into context may work briefly. On a long task it becomes slower and more expensive, and the current fact becomes harder to find. State needs selection and summarization for the next decision.

</Note>

<Note title="Being able to loop does not mean being able to self-correct" type="warning">

A loop only creates another chance to decide after seeing a result. Wrong tool data, a wrong acceptance condition, or a misread observation can still drive confident repeated failure. Verify with traces and targeted evaluations.

</Note>
