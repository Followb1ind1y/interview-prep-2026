## 三级回答

### Level 1 — 定义

ReAct 把推理过程和行动交替进行，用观察到的结果来更新下一步。

### Level 2 — 机制

Thought 帮助分解问题；Action 调用工具；Observation 是环境给的反馈。它是 loop 的一种提示格式。

### Level 3 — 工程

纯 ReAct 很难控制步数和费用。生产环境里更常用结构化的 tool calling + 显式的状态机 / 图，而不是自由文本形式的 Thought。

## Three-level answers

### Level 1 — Definition

ReAct interleaves reasoning traces with actions and uses what it observes to update the next step.

### Level 2 — Mechanism

Thought helps break the problem down; Action calls a tool; Observation is feedback from the environment. It's one prompt format for the loop.

### Level 3 — Engineering

Plain ReAct makes step count and cost hard to control. In production you usually see structured tool calling plus an explicit state machine or graph instead of free-text Thoughts.

## Interview questions

1. What problem with single-pass chain-of-thought does ReAct solve?
2. Why shouldn't you stop at ReAct?
3. In production, should the Thought text be shown to users?
4. How does it relate to a LangGraph state machine?
