<Locale lang="zh">

目标不是重新学一遍 AI，而是把已有 **3+ 年 LLM 工程经验** 转成 Interview Performance（面试表现）。

定位是 **Production LLM / AI Engineer**：能讲清模型机制，能建 RAG / Agent，能做评测、优化和部署，并能解释真实生产环境里的取舍（production trade-offs）。不要按纯 LLM Research Engineer 准备，也不要把 40% 时间花在 Transformer 数学上。

后期默认：**30% 学习 + 30% 项目深挖 + 20% 编码 + 20% 模拟面试**。拿到面试以后再调成 **20 / 20 / 30 / 30**。

<Note title="每天只记 6 件事">
定位：找什么工作。简历：怎么让别人愿意见我。项目：怎么证明做过。技术：到底懂不懂。编码：能不能写。面试：压力下能不能讲出来。
</Note>

## 怎么准备：面试问题，不是词条

侧边栏是地图。真正要写进子页的是问题。

例如 Attention：解释 self-attention。为什么是 O(n²)？MHA、MQA、GQA 有什么区别？长上下文为什么贵？KV cache 省了什么、占多少内存？

例如 RAG：怎么选 chunk size？为什么要 hybrid？检索差了怎么排查？文档对了答案却错了，为什么？RAG 和 fine-tuning 怎么选？

例如 Agent：agent 还是 workflow？工具失败怎么办？什么时候不要 multi-agent？怎么防 prompt injection？

例如 Harness：模型和 harness 的区别？context 溢出时保留什么？怎么做沙箱？agent 怎么知道自己写对了？

每页固定三级：

| 级别 | 问法 | 例子 |
| --- | --- | --- |
| 1 定义 | X 是什么？ | KV cache 是什么？ |
| 2 机制 | 它是怎么工作的？ | 检索是怎么工作的？ |
| 3 工程 | 什么时候会出问题，取舍是什么？ | Recall 90% 但答案准确率 70%，怎么诊断？ |

每个知识点最终只回答四件事：**是什么 → 怎么做 → 为什么 → 工程取舍**。项目例子写进 [项目深挖](/docs/projects)，不要在知识页堆完整项目介绍。

## 侧边栏怎么用

每一个知识点专栏都一样：**先点总览看计划和卡片，再进子页写答案。** 子目录默认收起；只有当前正在看的专栏会展开。

- **知识点**：九个专栏，再加工程基础 / 算法
- **面试表现**：项目深挖 + 行为面试
- Context Engineering 和 AI-Native Engineering 是这次补上的两块，不要跳过，也不要提前从 09 开始

系统设计页按题目练，不按架构 / 延迟 / 成本这些维度收藏。这些维度贯穿每一道题，知识本身写在 [Production AI](/docs/production)。

## How to prep: questions, not glossary entries

The sidebar is the map. What actually goes into each page is questions.

Attention, for example: Explain self-attention. Why O(n²)? MHA vs MQA vs GQA? Why is long context expensive? What does the KV cache save, and how much memory does it take?

RAG: How do you pick a chunk size? Why hybrid search? How do you debug bad retrieval? Why is the answer wrong when the right documents came back? RAG vs fine-tuning?

Agents: Agent vs workflow? What happens when a tool fails? When should you avoid multi-agent? How do you defend against prompt injection?

Harness: Model vs harness? What do you keep when context overflows? How do you sandbox? How does an agent know its code is correct?

Every page uses the same three levels:

| Level | The question | Example |
| --- | --- | --- |
| 1 Definition | What is X? | What is KV cache? |
| 2 Mechanism | How does it work? | How does retrieval work? |
| 3 Engineering | When does it break, and what is the trade-off? | Recall is 90% but answer accuracy is 70% — how do you diagnose it? |

Every concept ends up answering four things: **What → How → Why → Engineering trade-off**. Project examples go in [Projects](/docs/projects); don't pile full project write-ups onto concept pages.

## Using the sidebar

Every knowledge column works the same way: **open the overview for the plan and cards first, then go into the subpages to write answers.** Subsections are collapsed by default; only the column you're reading expands.

- **Knowledge**: nine columns, plus Engineering and Algorithms
- **Interview performance**: project deep dives + behavioral
- Context Engineering and AI-Native Engineering are the two newly added columns. Don't skip them, and don't jump ahead to 09

System design pages are practiced by problem, not collected by dimension (architecture / latency / cost). Those dimensions run through every problem; the underlying knowledge lives in [Production AI](/docs/production).
